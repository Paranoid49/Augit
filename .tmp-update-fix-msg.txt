fix(update): discover releases from Atom feed without API quota

Replace the anonymous GitHub REST release-list call with the public
Releases Atom feed. GitHub allows only 60 anonymous REST requests per hour
per IP; exhausting them made manual update checks fail with the raw
"Response status code does not indicate success: 403 (rate limit exceeded)"
message. The Atom feed is static, includes pre-releases, and is not subject
to that quota; it also keeps the update path out of the GitHub hosting API
that product-spec excludes.

- Select the highest SemVer tag from Atom entries and construct the signed
  update.json / update.json.sig asset URLs directly; signature, manifest
  validation, size and SHA-256 checks are unchanged.
- Map 403/429, other network failures, timeouts and invalid feeds to readable
  reasons instead of leaking HttpClient exception text; translate the new
  reasons in web/src/ui-text.js.
- Add UpdateService tests for Atom discovery, highest-version selection and
  rate-limit mapping, and update the ui-text regression assertions.
- Update auto-update/architecture docs, rc.15 known limitations and
  CHANGELOG. Live probe with the released rc.15 Atom feed and signed
  manifest resolves rc.15 from rc.14 as expected.

No new rc is published; this lands on main for the next release.
