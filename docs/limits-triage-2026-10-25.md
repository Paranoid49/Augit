## 3. 本轮实际完成/修复

### 3.1 纯 OS 键盘 NVDA 会话（rc.2）

- 工具：NVDA **2026.2 AMD64**（缓存便携运行时，Windows 11 25H2 26200.9457）；Narrator 可执行文件存在但本轮未作完整会话。
- 输入：`keybd_event` 的 **真实 OS 键盘**（方向/翻页/Home/End 带 `EXTENDEDKEY`），NVDA 睡眠模式
  `NVDA+Shift+S` 用于让页面接收导航键；**没有用 CDP/Playwright 注入被测键盘**。CDP 只读查询 DOM 几何/
  活动行/键到达情况，不参与输入。
- 小文件：NVDA+Tab 报 `small.txt Read-only content 区域 已聚焦`；NVDA+Down 朗读
  `alpha line onebeta line twogamma line threedelta line fourepsilon line five`。
- 2,001 行：从第 3 行开始，睡眠模式下 PageDown 到 **activeLine=1503 / line 1504**，
  `aria-activedescendant=virtual-line-1504`，`scrollTop=32628`；关闭睡眠后 NVDA 报
  `1504: line 1504 ... 当前，2001 之 1504 项`。继续 PageDown 到 **1523**，报
  `1523: ... 当前，2001 之 1523 项`。End 到 **2001**（空行），Up 到 **2000**，报
  `2000: ... needle line 2000，当前，2001 之 2000 项`。
- 80,001 行样本（9,748,894 B，行数 80,001；页面挂载 `mountedAt=1019.5ms`）：初始 DOM 30 行；
  PageDown 三次到 **line 61**，NVDA 报 `61: ... 当前，80001 之 61 项`；End 报
  `80001: ... 当前，80001 之 80001 项`；Up 报
  `80000: line 080000 ... needle 80000，当前，80001 之 80000 项`。
- 结论：**未发现新的焦点/行号/活动行/播报语义缺陷**；前一 rc.2 的 `aria-label` 修复在真实 OS
  键盘下继续成立。可访问树仍只有窗口行（80k 样本 30 个），全文连续朗读限制不变。

## 4. 高成本但可实施工程

**可变行高软换行虚拟化**：当前布局以统一 `rowHeight` 计算 `top`、总高、`visibleRange()` 和
`scrollTop`；换行后行高不同，必须同时引入：
- 行高/换行高度索引（前缀和 + 二分定位可视首行）；
- 绝对定位/窗口回收与滚动锚点；
- 选择偏移、拖动自动滚动、复制切片的全文偏移映射；
- Find 命中、Go to Line 居中、键盘 Page/End 导航；
- 可访问列表的 posinset/名称与当前行语义；
- 2,000 行先验证，再扩到 80,000 行/近 10MB，且不得恢复全量可访问树。
这需要设计+实现+回归，风险高，不能在本轮作为小修补；本轮明确登记为 1.0 后工程。**不把
`content-visibility`/分块全量 DOM 说成虚拟化。**

## 5. 未完成原因与建议

- 软换行/离屏全文连续朗读：成本高，非当前小修；已披露影响，建议 1.0 后专项。
- Settings 567/2904、500ms 历史慢样本：根因未复现；保留风险，不伪造修复。
- Windows 10/多屏/干净 VM/缺运行时/签名/真实日常使用：外部条件不具备；不能在本机伪称通过。
- 建议 rc.2 继续作为候选；正式 1.0 仍受 §4 条件与真实使用观察约束。
