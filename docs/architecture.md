# Augit 架构说明

后台批次对已显示的普通Text/TextReady文档仍重新读取磁盘；新旧完整显示模型一致时保留原模型，不写打开提示或请求正文重绘。只在原工作区、标签和文档身份仍有效时接纳同值结果，其他类型及失败沿原路径。见[同值正文刷新](refresh-same-document-2026-10-17.md)。

本文只规定如何实现[产品规格](product-spec.md)，不得新增、删除或改变产品能力。界面结构和视觉令牌必须遵守[UX/UI 规格](ux-spec.md)及[统一设计系统](design-system.md)；本文不维护实施进度。

## 1. 技术基线

- 使用 C#、.NET 10 构建 Windows 外壳，目标运行时为 `win-x64`。外壳只负责创建原生 Win32 窗口、承载 WebView2、执行本机 Git／文件／终端操作，不承载界面布局、文案或视觉规则。
- 界面本体是随程序分发的 HTML、CSS 和 JavaScript，位于 `web/`。主界面不使用 WPF、WinForms 或任何托管桌面控件框架，也不使用原生控件绘制正文。
- 视觉稿（`docs/ux-mockups/`）既是设计基线，也是运行时界面代码的来源。`mockup.js`、`mockup.css`、`current-find.js` 和 `image-preview.js` 在 `docs/ux-mockups/` 与 `web/src/` 之间必须**字节一致**，由 `tools/audit/verify-ui-assets.ps1` 强制校验；缺少这一步就会重新出现「视觉稿与实际界面各走一套」的漂移。
- 运行时依赖固定为 Microsoft WebView2 SDK `1.0.3650.58`、xterm.js `6.0.0`、`@xterm/addon-fit` `0.11.0`、ripgrep `15.2.0` 和 JetBrains Mono `2.304`（SIL OFL 1.1）。字体从独立开源仓库获取，四个WOFF2及许可证按SHA256锁定，视觉稿与运行时字节一致；WebView2实际加载后度量正文，加载失败沿回退链排版。按产品规格中2026-10-15用户裁决，等宽正文固定为随包JetBrains Mono 13，读取及保存时覆盖旧等宽偏好；界面外观按appearanceVersion迁移，随后保留用户的界面偏好。不引入前端构建链、包管理器或 Node.js 运行时；`web/` 下的文件按源码原样分发。
- WebView2 通过 `SetVirtualHostNameToFolderMapping` 把一个虚拟主机映射到 `web/`，再导航到 `index.html`。不使用 `file://`，也不把界面资源释放到临时目录。
- 界面资源按需读取，不在启动时枚举或预读整个 `web/`。
- 外壳在文档创建时注入错误收集脚本，把 `error` 与 `unhandledrejection` 记录到 `window.__augitErrors`，供验收套件断言「没有未捕获异常」。
- 普通文本与 diff 都由 HTML 视图渲染，共用同一套 CSS 与交互绑定；不引入自绘文本控件，也不分发文本控件库。
- 图片解码使用 Windows Imaging Component；首版只支持 PNG、JPEG/JPG 和 BMP，不支持 GIF 与 WebP 预览。
- Win32 互操作使用项目内最小 P/Invoke 声明，不引入 Win32 包装框架。
- 关键依赖可以升级，但升级前必须说明收益和运行时成本，升级后重新执行功能、兼容性和性能测试。切换技术栈属于架构决定，必须获得用户明确授权。

## 2. 模块边界

WebView2初始化在环境创建、控制器创建及脚本注册的异步续接处检查窗口是否已销毁；迟到控制器须立即关闭并清引用。关闭后的初始化或捕获异常不得弹框或通知所有者，以免旧设置影响新窗口。此保护不改变准备和呈现顺序。

正常WM_CLOSE和WM_DESTROY也记录设置关闭阶段并在销毁后后台导出，与显式Dispose路径共同覆盖释放；所有者启用、撤下合成画面、DwmFlush、激活和控制器Close分别计时。诊断不改变执行顺序，不增加同步等待，缺失最终阶段不得判为关闭通过。详见settings-close-stages-2026-10-17.md。

设置原生阶段诊断仅在内存保存最多64条阶段名、单调时间戳和线程号，并保留UTC锚点。呈现或释放后，显式环境变量 `AUGIT_SETTINGS_TRACE_DIRECTORY` 指向已存在绝对目录时，以后台 CreateNew 文件导出；导出失败不改变产品流程，不增加界面等待。消息阶段仅记录已知协议名，未知内容归为固定标识，不读取用户输入或文档。原生阶段不代替桌面呈现、字体或关闭验收；进程退出前未完成导出时必须登记证据缺失。

设置自身捕获的capture-start、capture-issued、capture-end分别标记调用前、返回Task后和await完成后，区分同步调用与异步等待；仍等待原任务，销毁保护和揭示顺序不变。

- `Augit.Core`：工作区、文档分类、UTF-8 校验、显示规则、Git 状态语义和操作会话等稳定规则。不依赖界面技术、文件系统或进程类型。
- `Augit.Infrastructure`：本地文件读取与监听、Git、ripgrep、ConPTY、设置持久化和外部程序适配。
- `Augit.Shell`：Win32 窗口生命周期、WebView2 宿主、消息桥接、单实例激活和命令行解析。不承载文件格式或 Git 业务规则。
- `web/`：界面结构、视觉令牌、区域渲染、交互绑定和实时数据装配。不直接访问文件系统或 Git，只能通过消息桥接请求能力。

### 2.1 消息桥接

- 网页通过 `chrome.webview.postMessage` 发送 `{ id, method, params }`；外壳执行后以 `PostWebMessageAsJson` 返回 `{ id, result }` 或 `{ id, error }`。
- 外壳主动推送的事件使用 `{ event, payload }`，**不带 `id`**，因此与请求响应共用同一条回复队列而不冲突。事件与请求必须靠 `id` 的有无区分，不能用消息顺序推断。
- 桥接方法按能力分组：`workspace/*`（信息、目录、变化）、`document/read`、`git/*`（状态、历史、blame、文件历史、提交、差异、引用、远端、stash、worktree、冲突状态、clone）、`search/*`（文件、正文）、`settings/*`（读、写）、`terminal/*`（启动、读、写、缩放、停止）。
- `window/modal-*`只承载窗口生命周期：网页提供表单身份、祖先、标题及裁切矩形；外壳校验信封及有限尺寸，在窗口线程串行呈现。关闭立即淘汰旧捕获和排队请求；允许之后打开新表单。窗口线程之外的调用明确拒绝，异常不得穿过原生窗口消息过程。
- 桥接只回传结构化结果，不回传 .NET 异常原文。校验类失败（参数缺失、路径越界、未知方法）回传本应用写好的结构化提示，由界面层统一为英文；文件系统类失败回传统一的可读说明；其余兜底只给出异常类型名，避免把实现细节暴露到界面。
- 路径参数一律经工作区越界校验后使用。校验在比较前给根路径补目录分隔符，因此不存在「前缀相同但实为兄弟目录」的绕过。

### 2.2 区域渲染

- 界面按命名区域渲染：`titlebar`、`rail`、`side`、`editorTabs`、`editorContent`、`statusbar`、`bottomTool`、`overlay`、`toast`。
- `window.__augitRenderRegions(...names)` 只替换指定区域，保留其余区域的 DOM 实例、焦点、滚动位置和展开状态。全局重绘只用于结构性变化（例如工具窗口的出现与消失），不得用于局部状态更新。
- 区域替换**只在目标与替换节点两侧都存在时**执行；某个区域在该场景下不存在时跳过，不因此退化成整页重绘。
- 状态局部刷新仅在目标包含side时尝试改动列表补丁；已被补丁吸收的唯一目标不得以空参数调用全局刷新，避免外部目录变化销毁无关弹窗与输入。正常入口修前/修后证据见[局部刷新范围修复](refresh-region-scope-2026-10-17.md)。
- 改动列表补丁、提交反馈及工具栏仅在值实际改变时写DOM；分组计数复用初始渲染函数，避免同值通知或文案漂移触发无效背景截图。真实变化与错误恢复仍更新，正常入口证据见[同值刷新记录](refresh-noop-dom-2026-10-17.md)。
- 外部文件变化批次成功重读普通文档时，将区域渲染交回批次收尾，避免openDocument和批次重复刷新。用户主动打开保留事件后刷新和等待契约，失败仍即时反馈，删除判断与串行消费保持；见[批次渲染记录](refresh-document-batch-2026-10-17.md)。
- 设置回读在异步字体度量结束后重新检查请求代次、工作区及配置对象身份，过期续接不得恢复旧面板或标记就绪；正常入口及竞态证据边界见[回读保护](settings-reload-generation-2026-10-17.md)。
- 连续设置回读按同一live对象及四项字体参数共享在途字体任务；新回读不能因配置值已更新而跳过等待。不同字体创建新任务，旧任务仅清理自己，失败保持未就绪并允许重试。见[共享字体等待](settings-shared-typography-2026-10-17.md)。
- 主窗设置事件将持久化回读与临时主题预览分别计代；旧回读可更新已保存配置，但不能覆盖等待期间较新的预览。取消后的新回读仍恢复持久化主题，见[预览顺序](settings-preview-generation-2026-10-17.md)。
- 独立设置OK等待持久化成功后直接关闭，省去子窗配置回读与字体度量；主窗仍由committed/closed通知更新，Apply与共用页面仍回读。见[关闭回读整改](settings-ok-no-reload-2026-10-17.md)。
- 由指针或键盘事件触发的刷新必须推迟到当前事件派发结束之后（`refreshAfterEvent`）。事件处理挂在 `document` 的捕获阶段，而视觉稿自身的监听挂在冒泡阶段；在捕获阶段同步替换被点击的元素，会让它在事件继续传播前离开文档，冒泡阶段的监听再也收不到事件。
- 区域替换前调用 `disposeRegionBindings()` 释放「所有者是被替换节点、但监听挂在 `document`/`window` 上」的绑定，避免监听随刷新次数累积。

### 2.3 状态与数据

- 工具窗口尺寸以 `ToolWindows.WorkspaceRoot` 保存归属，与标签会话 `LastWorkspace` 分开；旧配置缺少归属时读取按原 LastWorkspace 判断，会话转移前固定旧尺寸归属。仅拖分隔条不转移旧工作区标签。网页 Git 写入、网络与取消请求统一等待宿主真实结束；有限网页超时只用于读取，不能代替本机进程停止。

- 审计可显式传入 `--settings-file <完全绝对文件路径>` 和 `--user-data-folder <完全绝对目录路径>`。两参数分别隔离本实例的配置和 WebView2 profile，完整隔离必须同时指定；普通启动仍使用用户默认路径。启动、桥接设置／会话读写与窗口保存共用该实例的 SettingsStore；隔离实例不参与用户窗口复用或登记，显式 profile 不清理默认历史会话目录。这是审计 CLI 入口，不加入产品页面。`workspace/open` 派生新窗口暂不继承隔离参数，取证不走该真实新窗出口；`--no-session-restore` 只控制恢复，不代表隔离。

- `settings/fonts` 为只读按需桥接，外壳用Win32枚举字体族并仅缓存名称列表；设备上下文在枚举结束后释放，不引入GUI框架或后台服务。网页在首次打开设置时请求，结果就地补入下拉选项并保留当前草稿。

- 外壳返回的数据在写入界面状态前必须校验契约。缺少身份字段（`path`、`rows`、`lines`、`commits` 等）的载荷按失败处理，**不得**把字段缺失的对象留在状态里——那会让后续每一次渲染都依赖调用方的容错。
- 异步加载一律带递增令牌，晚到的旧响应直接丢弃：工作区变化与文件监听事件可能让两次读取交错，不做这一步就会出现「慢的旧结果覆盖用户最后一次选择」。
- 交互产生的用户状态（改动列表勾选、提交草稿、选中行、滚动位置、工具窗口布局、标签集合）保存在界面状态中，不能只放在 DOM 上——区域刷新会重建节点，只放 DOM 的状態会被静默丢弃。
- 进程内缓存必须在前提条件改变后失效。例如 Git 解析结果在 `git.exe` 路径设置变化后清空，否则用户改好设置也必须重启才能生效。
- 编辑器标签集合见 UX 规格 §5.2：`live.tabs` 按显示顺序保存，`live.activeTabId` 指向当前标签；`live.document` 与 `live.editor` 是当前标签的派生视图。

## 3. 只读与写入边界

设置揭示阶段在自身CapturePreview完成、退出异步回调后的窗口消息中先DwmFlush，再解除cloak；不增加固定延时、不展示截图、不改变主窗控制器。单份769帧未重现此前白窗，但仍为候选修正，不代表所有场景无闪。诊断额外记录创建控制器、注册启动脚本、导航与准备/渲染/揭示的单调时刻，以及创建、控制器完成、脚本注册完成和捕获完成的托管线程ID；只记录观测，不引入新的调度策略。六次正常入口上述续接线程均与创建线程相同，不能将慢开直接归因跨线程。正常入口仍存在秒级慢开，见settings-ready-queue-2026-10-17.md与settings-no-cdp-origin-2026-10-17.md。

设置首次准备显示与最终呈现都由原生窗口消息处理。网页的 window/settings-ready 仅登记请求并投递 SettingsPrepareMessage；退出 WebView 消息回调后再执行 cloak、尺寸同步、控制器显现、原生不激活显示及位置通知，完成才应答。关闭或所有者销毁后不处理排队准备消息；失败释放本次子窗。该顺序避免首次显示在 WebView 回调内同步派发窗口消息，不增加等待、截图层或预创建控制器。准备阶段保留单调时钟分段，不能把驱动点击等待、控制器创建和原生显示混算成同一延迟；此调整不构成全部慢开已解决的声明。

2026-10-17首层模态定位订正：网页裁切相对主窗客户区，以ClientToScreen取得客户区屏幕原点；不得使用包含最大化外扩边距的GetWindowRect原点。嵌套模态继续相对已移动父窗定位。此修复不改变系统阴影与遮盖，残余闪帧仍未通过，见[定位证据](refresh-client-origin-2026-10-17.md)。

2026-10-16用户授权的设置窗口例外：Settings使用独立owned Win32窗口和独立业务WebView2Controller，主窗口原控制器持续呈现，不重挂、不隐藏、不创建设置背景截图或刷新遮盖。只挂载共享HTML/CSS设置表单，不复制主界面、标签、终端或工作区监听。独立设置导航settings-surface.html精简入口，复用mockup.css和live-data.js，不加载xterm库、图片预览与当前文件查找脚本；普通主窗仍使用index.html。窗口复用同一CoreWebView2Environment、ShellBridge和SettingsStore；设置页面仅允许设置读写、字体枚举及Git检测。创建期间先登记唯一子窗，重复入口只激活现有窗口；页面就绪后显示，初始化失败或超时释放并恢复所有者。宿主跨设置页面生命周期串行保护设置写入，成功递增版本通知主窗；取消可立即关闭，迟到应答不得访问已销毁控制器或关闭新窗口。主题预览同步主窗与设置WebView原生底色；保存更新当前模式，取消和异常关闭恢复已提交模式，新开设置使用当前生效主题。异步保存续接只投递主题消息，原生UI线程更新COM底色；关闭回读持久值，Apply成功留窗。独立设置首次装配复用当次settings/read结果，只在完整表单装配后执行字体度量；关闭及提交通知仍回读最新设置，不缓存后续配置。首次呈现以DWM cloak启动合成；页面不等待隐藏动画帧。宿主通过一次CapturePreviewAsync把设置自身的渲染结果写入Stream.Null后丢弃，只作渲染同步，不展示截图、不复制主界面。显示、激活和控制器焦点经原生窗口消息队列在cloak期间先完成，再等待设置自身CapturePreviewAsync确认渲染；完成后投递独立揭示消息，仅解除cloak，避免此前确认的表面在激活时失效。搜索框的初始DOM焦点在window/settings-present之前设置并禁止滚动，使其也包含在宿主最终渲染确认内；揭示后不补做初始焦点。揭示后不重复显示、激活或设置控制器尺寸；仅此设置HWND禁用系统过渡动画，不更改全局系统设置。展示时禁用所有者；关闭时先启用所有者、撤下设置的DWM合成画面并同步，再激活所有者和销毁设置，避免仍可见的窗口先变成非活动阴影；异常释放也先撤下画面再关闭控制器。首次开窗仍有偶发秒级延迟，不能宣称性能验收完成。以下截图与单业务控制器重挂规则仅适用于其他模态。新增设置renderer的成本须按实例进程树测量，不预先宣称内存降低。

背景刷新PNG通过WebView2的Page.captureScreenshot捕获当前业务合成表面，采用快速无损编码、固定当前视口，不复制业务DOM或启动额外调试服务；初始背景仍由CapturePreviewAsync取得；遮盖首图与复用截图也采用同一快速PNG路径，保留图片加载、两帧确认和DWM队列保护。响应校验后沿现有图片版本队列替换。背景刷新应答等待对应版本onload完成，不能以设置src的脚本提交完成替代；失败或关闭在窗口线程结束等待，先清登记再唤醒以允许同步重入释放。此确认不代表桌面已呈现，仍保留网页恢复及撤盖保护。快速编码增加PNG与临时Base64占用，测量及仍未解决的闪帧见[表面捕获记录](pixel-refresh-surface-capture-2026-10-15.md)及[遮盖提速记录](pixel-refresh-fast-cover-2026-10-15.md)。

除上述Settings例外，其余独立模态仍由共享网页渲染，owned Win32窗口重挂同一个业务WebView2Controller，保留完整网页视口并裁切；DOM、草稿、监听和桥接不复制。所有者禁用，嵌套关闭返回原表单，最终回到主窗口。背景由截图WebView2显示内存PNG：主界面变化刷新全部背景，父表单变化只刷新自身及更上层背景，顶层草稿不触发捕获；文本节点按所属元素归属。每层最多保留显示图、在途图和最新待发送图，慢加载合并中间版本；每次WebResource响应共享只读字节数组并使用独立流游标，新图加载后释放旧图和旧流。关闭逐步释放短期控制器、图片、流和窗口，一步失败仍执行剩余清理，迟到回调不得恢复已关闭资源。业务控制器只跟随最上层DPI，每层裁切和快照跟随其所属窗口；移除表单取消ResizeObserver监听。捕获时的透明帧、额外renderer和浏览器缓存仍需优化；系统阴影定量、真实跨屏及全表单同态配对仍待验收，成本与证据见[字体与窗口记录](pixel-font-followup-2026-10-13.md)。

- 普通文档接口只暴露读取结果，不暴露保存、替换或写流能力。
- JSON 格式化、Markdown 渲染、换行和空白符显示都只生成内存中的显示结果。
- 用户主动执行 Git 操作时，由本机 Git 进程修改索引、引用或工作区。Augit 不绕过 Git 直接模拟 checkout、merge、reset 等文件写入。
- Git 写操作必须通过明确的应用用例执行。命令失败时只在当前操作界面临时显示经过脱敏的命令结果，不建立 Git 控制台、操作历史或持久化日志。
- Augit 不提供冲突结果写回或任何内置文本保存用例；冲突由外部编辑器或终端解决，Git 已跟踪结果由用户显式执行 `git add`。界面只读取消或跳过操作不得改写冲突文件。
- 外部工具改变文件或 Git 状态时，界面刷新读取最新磁盘事实，不把缓存冒充真实状态。

## 4. 文件与预览安全

- 文本读取在分配大缓冲区前检查文件长度，只接受有效 UTF-8，可识别并去除 UTF-8 BOM。
- 文件分类先识别受支持图片，再匹配其他已知二进制签名和 NUL 字节，其余内容执行严格 UTF-8 校验。非法 UTF-8 归入二进制摘要，不替换成乱码显示。
- 文本上限 10 MB，图片上限 25 MB 且解码像素上限 2500 万。超限返回带具体上限的可读说明，不静默截断。
- 只有 `TextReady` 结果才附带编码与换行信息；二进制摘要、超限和不可预览结果不得声明编码，避免让用户以为它们是文本。
- 目录符号链接和目录联接不递归。普通文件符号链接显示解析后的目标路径；本机固定磁盘上的工作区外目标允许只读访问，网络、远程、失效和循环目标拒绝读取。
- 工作区相对路径在拼接后必须重新规范化并校验仍位于工作区内，越界请求返回可读原因。
- Markdown 预览的本地资源在规范化并解析符号链接后必须仍位于工作区内；越界资源不加载。
- Markdown 禁用原生 HTML，HTML 标签转义为普通文本；渲染模板由 Augit 控制，不引入 Sanitizer。
- 远程图片只允许 HTTP 和 HTTPS，并且只在用户打开 Markdown 预览时加载；正文 DOM 就绪不等待远程图片，图片失败只替换对应容器并显示原因。HTTP、HTTPS 和邮件链接交给系统，绝对本地路径、越界路径和未知协议阻止处理。

## 5. Git 与外部进程

状态读取中的status、branch与HEAD三项只读查询并行启动；统一等待所有进程退出，再沿原错误优先级处理。保持命令、输出边界及取消契约，不提供原子快照保证。正常入口收益及首次超时限制见[三路并行记录](refresh-status-three-parallel-2026-10-17.md)。

- Git 定位顺序为用户设置路径、系统 `PATH`；不从仓库内寻找或捆绑 `git.exe`。Git for Windows 2.40 是整个 Git 模块的最低版本，缺失或低于该版本时禁用 Git 能力，但保留文件浏览与 Git 路径设置入口。
- Git 不可用是独立状态，与「不是 Git 仓库」区分：前者显示一次含配置入口的局部提示且不重复弹出，后者静默。
- 每条 Git 命令明确以当前工作区为工作目录，继承本机 Git 配置、凭据助手和 SSH 环境。
- 提交历史使用 `--topo-order`。默认按提交时间排序会让 rebase、cherry-pick 和合并产生「父出现在子之后」的顺序，泳道推导会因此画出回边。不使用 `--graph`：图形由界面按父提交关系自行推导，该开关在大仓库上额外付出遍历成本而没有消费方。
- 文件复选提交完全使用本机 Git：先对选中的未跟踪文件执行 `git add`，再使用 `git commit --only` 和选中文件路径提交磁盘完整内容；不建立 Augit 自有索引事务，不把未选中的既有暂存项带入提交。
- Conventional Commits 1.0.0 兜底校验属于 `Augit.Core` 规则，只处理用户手工输入的 Commit 和 Amend 信息；仓库规则和 Git 自动生成的信息绕过该兜底规则，但仍完整执行本机 hooks。
- Git 状态以 HEAD、索引和工作区的最新本地事实为准；远端状态只在用户主动 fetch 或 pull 后更新。
- 文件监听和 `.git` 状态监听事件合并刷新，目标是在 500 毫秒内反映本地变化，不通过持续扫描或后台 fetch 实现。普通文件系统观察器的合并窗口为 20 毫秒，`.git` 元数据观察器保持 50 毫秒；窗口只合并同一次保存的重复事件，效果与回归见[合并窗口记录](refresh-watcher-merge-2026-10-17.md)。
- 外部文件刷新等待状态后重新核对当前文档、读取代次和在途读取；用户已切换时只更新仍存在且版本未被替换的后台标签，不推进前台读取代次或覆盖前台加载提示。关闭、工作区更换和同文件新读取使后台结果失效；详见[竞态整改](refresh-background-tab-race-2026-10-17.md)。
- 网页工作区变化消费从宿主取批到界面应用串行执行；在途推送与兜底通知合并为下一次读取，不重放载荷、不按路径吞掉后续真实变化。当前批次失败后继续处理已登记唤醒，不让旧批次晚到覆盖本入口的新批次。正常入口仍未达500毫秒，见[串行消费记录](refresh-serial-delivery-2026-10-17.md)。
- 状态读取带短时缓存并由文件系统事件失效；重复请求在缓存窗口内复用同一次查询。
- 同一界面变化批次共用一次最新状态读取，跨批重新查询。仓库探测仅并行互不依赖的裸仓库属性/公共目录、根目录/未合并索引；状态解析成功后并行读取分支名/HEAD。每组等待全部结束再按原顺序处理错误，取消沿用进程树清理；不改变缓存失效和写操作串行规则。实际性能及未达标边界见[刷新状态整改](refresh-status-batch-2026-10-17.md)。
- 所有外部进程都支持取消、输出边界、退出码和稳定错误结果；认证信息和敏感环境变量不得进入界面错误输出。本地只读 Git 查询设置 30 秒自动超时，网络与 Git 写操作不设置自动超时，只响应用户主动取消；取消后重新读取仓库实际状态，不自行删除 Git 锁文件或伪造回滚结果。
- merge、rebase、cherry-pick 和 revert 的操作会话以 Git 元数据目录中的真实标记、未合并索引项和暂存差异为准；Continue、Skip 和 Abort 只在当前 Git 状态实际支持时显示，不能由界面缓存推断成功。
- Smart Checkout 只使用本机 Git 创建带唯一 Augit 标记的临时 stash，完成切换后再由 Git 恢复；恢复冲突保留 stash 并进入统一冲突流程，重新打开窗口后可从 stash 标记恢复会话，不建立 Augit 自有索引事务。
- 冲突状态由本机 Git 的未合并索引项、操作元数据和工作区事实读取，普通文档服务只提供只读内容。2026-10-17 用户批准移除三栏编辑后，不再读取 stage 2/stage 3 生成可编辑三侧，也不提供逐块接受或结果保存。
- `git/conflicts`及操作会话只返回冲突文件列表、操作类型、步骤与动作可用性；不返回可编辑三侧内容，也不保留结果区间身份。
- 设置保存按窗口会话归属草稿、保存中、失败、已保存状态；全局写入单飞，取消允许关窗，旧应答不得关闭新窗或覆盖新草稿。保存等待宿主实际完成，不以客户端超时解锁第二次持久化；Enter尊重焦点按钮，原生选择框与IME保留自身语义。
- 冲突文件不提供结果保存入口；外部工具解决并暂存后，状态读取按本机 Git 事实更新冲突列表与 Continue/Skip/Abort 可用性。
- 文本 diff 在读取两侧内容前分别检查 10 MB 上限，生成过程中检查 20 MB 输出上限；任一超限立即停止正文生成并返回摘要。
- 工作区 Diff 只缓存一份当前文件补丁，单栏/双栏切换复用该补丁，不重新调用 Git；文件或比较选项变化时替换缓存，关闭工作区 Diff 或销毁窗口时释放。请求键必须覆盖全部影响结果的维度（仓库、路径、比较基准、显示模式、忽略空白、重命名检测与内容版本），否则切换选项会错误复用旧补丁。
- `Ctrl+P` 调用 ripgrep 时始终应用 `.gitignore`；全仓搜索的「包含忽略文件」不能取消对 `.git` 的永久排除。当前文件搜索和全仓搜索默认使用字面量模式，并把区分大小写、全字匹配和正则开关映射为明确参数。
- 全仓搜索在第 1001 条结果出现时终止 ripgrep，并显示统一的截断提示；默认总超时为 15 秒。
- 内置终端通过 Windows ConPTY 连接 shell，界面侧使用 xterm.js 负责显示、ANSI 控制和键盘交互，`@xterm/addon-fit` 同步行列尺寸。两者均为 MIT 许可证，发布产物只包含锁定的 JavaScript、CSS 与许可证文本。
- 每个内置终端会话使用独立 ConPTY 与带 `KILL_ON_JOB_CLOSE` 的 Windows Job Object；关闭时先结束 Job 中的 Shell 与子进程树，再清理该次会话资源。
- 关闭空闲终端时直接结束 shell；存在前台命令时先确认，再终止 shell、前台命令及其整个子进程树。

## 6. 性能设计与验收口径

### 6.1 启动与常驻资源

- 启动路径不扫描整棵目录、不读取 Git 全历史、不创建终端会话。
- 文件树仅枚举用户当前展开的目录；Git 历史分页读取。
- 外部变化由事件驱动并合并处理，空闲时不轮询整个仓库。
- 同一工作区只允许一个实例；再次启动只激活已有窗口并退出，不重复初始化界面。单实例识别使用按工作区路径命名的内存映射登记窗口句柄，**不能**依赖窗口标题匹配：WebView2 下文档标题变化通知不可靠。
- 主题在外壳启动时解析一次（命令行 > 设置 > 系统），设置保存后立即生效，不需要重启。设置为跟随系统时，外壳监听 `WM_SETTINGCHANGE` 中区域名为 `ImmersiveColorSet` 的系统应用模式变化，重新解析主题并以 `theme/changed` 事件下发给界面；用户显式选择浅色或深色时该事件不推送，系统变化不覆盖用户选择。主题切换只替换颜色与资源，不改变尺寸、间距、布局或交互状态。
- 生效主题下发给网页层时**统一为小写查询值**（`theme=dark`／`theme=light`），由 `ShellTheme.QueryValue` 归一化。设置里的取值是 `System`／`Light`／`Dark`，网页层的契约是小写；直接下发生效主题会让 `theme=Dark` 无法被识别，使深色主题在真实应用里失效，而审计与视觉稿一律用命令行小写参数、走"显式主题原样返回"的分支，因此不会暴露该缺陷。
- 系统深色检测失败（注册表不可读或取值不可用）时按**非深色**处理，不做"检测不出来就当作深色"的假设；这与参考实现一致（其 `isSystemThemeDark()` 返回可空值，调用方遇到失败直接返回、不切换主题）。

### 6.2 正式测量口径

- 使用 Release、win-x64 发布版，不连接调试器。安装版为 framework-dependent，便携版为 self-contained；性能对比必须注明被测形态，不能把两种发布形态的运行时加载差异混入同一组结论。
- 冷启动从创建进程开始，到主窗口完成首次渲染并能够响应界面输入为止。1 秒是优先优化目标。
- 内存统计 **Augit 主进程与它派生的 WebView2 进程树之和**。只统计主进程会严重低估真实占用；只统计 `msedgewebview2` 进程还会把其他应用的浏览器进程算进来（实测曾因此把 525 MB 误报成 822 MB）。必须按父进程关系归属到本实例。
- 正式测试使用 10 万文件测试仓库，记录 Windows 版本、CPU、内存、磁盘、.NET Runtime、发布方式和测量结果。
- 测试机不得存在 E-SafeNet 等第三方进程注入。无法避免时只记录诊断数据，不宣称通过或失败。

### 6.3 内存口径说明

- WebView2 采用 Chromium 多进程架构（浏览器、渲染、GPU、网络等），其固有开销远高于同功能原生控件。这是「界面本体使用 HTML/CSS/JS」这一技术选择的直接成本，不是实现缺陷。
- 因此 100 MB Working Set 目标在当前技术基线下不可达。已记录的实测值约为 525 MB（主进程约 62 MB + WebView2 进程树约 464 MB）。
- 若需要满足量级更低的内存目标，唯一途径是改用自绘或原生控件界面，代价是放弃视觉稿与 HTML/CSS 的复用关系。这属于架构决定，必须获得用户明确授权。

### 6.4 性能不达标处理

- 任何超出目标的测量都必须保留可复现的测量方法、原因分析和下一步优化记录。
- 优化前必须先确认测量本身正确：分辨「真实变慢」与「测量口径错误」。历史上有多次结论因测量工具缺陷而被推翻（汇总接口看不见监听移除、测试桩无法表达乱序返回、进程归属未按父进程计算）。

## 7. 本地数据与分发

- 设置、最近目录、窗口、标签和文件树展开状态只写入 `%LOCALAPPDATA%\Augit`，不向工作区写 Augit 配置。
- 设置写入只接受已知取值：主题限定 `System`／`Light`／`Dark`，终端 Shell 限定已登记的标识，字号限定在 9–40。写入未知值会让界面显示与运行时行为不一致。
- 设置文件损坏（非法 JSON、被截断、空文件、字段类型错误）时一致回退默认值，并在下一次写入时修复文件，不阻塞启动。
- 内置终端首次默认启动 Windows PowerShell，用户主动选择后才使用其他 shell 或自定义命令；配置失效时返回明确错误，不静默回退。xterm.js 的 scrollback 固定为 2000 行。
- 关闭空闲终端时直接结束 shell；存在前台命令时先确认，再终止 shell、前台命令及其整个子进程树。
- 安装版为 framework-dependent，依赖 .NET 10 Runtime 和 WebView2 Runtime，不依赖 .NET Desktop Runtime；正式产物的 .NET 兼容下限以 `Augit.runtimeconfig.json` 为准；缺失 .NET 时，安装版先向用户说明，经确认后从微软官方下载并安装锁定版本。
- 运行时具体版本、微软官方下载地址和完整性信息统一维护在[运行时依赖锁定基线](runtime-dependencies.md)中。便携版为 self-contained，自带 .NET 10 Runtime，不使用安装版的 .NET 下载流程；它仍依赖 WebView2 Runtime，但不会安装或修改共享运行时。
- 提供安装版和便携压缩包：安装版是 framework-dependent 联网安装器，便携包是 self-contained 解压即用包。2026-10-26 用户批准该分发策略，替代此前“不提供 self-contained 包、便携包不安装运行时”的约束；该变更只影响分发方式，不改变技术栈、产品行为或进程模型。
- 随程序分发的可执行文件、前端库和 NuGet 依赖必须附带相应许可证。

## 8. 验证方式

- **逻辑与交互**：无头浏览器验收套件（`tools/audit/live-shell.spec.cjs`）用桩宿主驱动真实界面代码，逐条断言规格条款。它不依赖桌面和 WebView2，因此可以在同一轮里跑完整套而不拖慢反馈。
- **真实外壳**：渲染保真度、启动耗时、内存和视觉稿像素比对必须在真实外壳中测量（`tools/audit/shell-capture.ps1`）。断言优先于截图：`PrintWindow` 对 WebView2 的底部与状态栏区域不可靠。
- **视觉稿一致性**：`docs/ux-mockups/` 下的场景页在真实浏览器中逐个渲染，与运行时共用同一套资源；资源字节一致性由 `verify-ui-assets.ps1` 校验。
- 断言必须能区分「实现正确」与「实现错误」。新增断言或修复后应做负向验证（临时移除修复，确认断言确实失败），否则无法排除「断言恰好通过」。
- 桩必须是异步的，才能表达乱序返回；桩的取值不能与默认值相同，否则无法区分「读到了桩」与「用了默认值」。
