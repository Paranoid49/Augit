# Augit 架构说明

本文只规定如何实现[产品规格](product-spec.md)，不得新增、删除或改变产品能力。界面结构和视觉令牌必须遵守[UX/UI 规格](ux-spec.md)及[统一设计系统](design-system.md)；本文不维护实施进度。

## 1. 技术基线

- 状态栏从活动普通标签或活动比较取得路径；编码和换行仅使用 `DocumentReadResult` 的文本元数据。文件服务在原有完整 UTF-8 字节上识别换行，不复制内容或追加读盘；JSON 格式化不修改磁盘元数据。文档读取结果变化通知仅更新活动状态栏，字段和提示未变时不重新度量、改写控件或重绘。格式宽度按当前界面字体缓存，取消按钮局部定位；绘制不读文件、不查询 Git、不调用主窗口布局，也不增加线程、窗口或依赖。完整状态复用已有 Tooltip 和辅助功能文字。

- 使用 C#、.NET 10 和原生 Win32 构建 Windows 主界面，目标运行时为 `win-x64`；`Augit.App` 不启用 WPF 或 WinForms，不引入托管桌面框架。
- 首版重建基线固定为 Scintilla `5.6.6`、Markdig `0.41.3`、Microsoft WebView2 SDK `1.0.3650.58`、xterm.js `6.0.0`、`@xterm/addon-fit` `0.11.0` 和 ripgrep `15.2.0`。
- 随仓库保存的 Scintilla、ripgrep、xterm.js 和 `@xterm/addon-fit` 运行时文件统一记录在 `tools/runtime-assets.lock.json`；发布前校验源文件，发布后再次校验复制结果的大小和 SHA-256，锁定失败时不生成或替换最终产物。
- 主窗口、文件树、标签、列表、工具栏和状态栏使用 User32 与 ComCtl32 原生控件；普通文本、diff 和冲突文本使用 Scintilla 原生控件。普通文本和 diff 始终只读，只有冲突结果区允许解除只读。
- Scintilla 文本使用控件内置的 DirectWrite 渲染路径，统一字体解析、分数字号和抗锯齿；仍使用 Windows 自带的 DirectWrite/Direct2D，不增加分发依赖或后台进程。
- Diff 的字符样式、字词高亮和整行底色使用 [Scintilla 官方直接调用接口](https://www.scintilla.org/ScintillaDoc.html#DirectAccess)，减少逐行调用 `SendMessage` 的开销。每个控件单独保存原生上下文，仅在创建它的线程使用直接调用；跨线程保留 Win32 消息同步。装饰批次开始时验证 HWND 有效，销毁时清空上下文和委托，不改变 UTF-8 偏移、只读、选择、滚动或现有请求版本规则，不引入新依赖、正文副本或常驻进程。
- 工作区、历史、引用及文件历史比较通过 Scintilla 背景标记绘制整行增删色，字词指示器独立叠加。颜色由 `NativeTheme.DiffColors.cs` 与视觉稿统一，外观变化仅更新标记颜色；分批装饰完成时再次应用当前主题，避免旧时间片恢复旧颜色。替换正文时清除旧行标记，空行按其换行符定位，补齐的空白侧不登记变更。不新增正文副本、依赖或后台资源。
- 工作区、历史和引用 Diff 的大批量装饰每 64 项检查一次耗时，达到约 4 毫秒后通过可取消的短延迟返回 Win32 消息循环；恢复前同时核对控件正文版本、请求有效性、取消和销毁状态。样式起点与写入、高亮编号与填充保持成对，不跨时间片拆开。小批量无需等待；普通同步装饰复用同一命令序列。这里限制连续装饰时间，不承诺单次原生调用或系统调度的硬实时上限，也不把这些诊断用例作为正式性能验收。
- 界面字体、界面字号、等宽字体和等宽字号独立解析、应用和保存，默认字号均为 13px（96 DPI 逻辑像素）。原生控件、Scintilla 和按需 WebView2 按设计系统中的文字角色使用对应设置，不共用一个字号覆盖两类文字；DPI 换算和字体度量不能改变用户保存的逻辑字号。
- `NativeTheme` 缓存界面正文、半粗体和斜体的最大实际行高，字体、字号或 DPI 改变时与字体句柄一同失效；布局与绘制复用该值，不逐帧创建测量上下文。主框架文字容器保留默认尺寸下限，按设计系统扩展；树行高更新后恢复原首个可见节点，文档复用控件并重新排布路径工具栏。主菜单、状态格式及取消动作按实际字宽分配；底部工具窗口的最小高度复用同一行高，使用 `max(180px, 4h + 80px)`，不重查 Git 或重建编辑控件；品牌使用固定字号缓存字体，不增加依赖、线程或常驻进程。
- 主框架分隔条保存按下指针与当时可见尺寸，移动和释放共用布局的尺寸夹取函数；尺寸未变直接返回，不调用全局布局或写入设置。实际拖动更新原有持久化字段，Esc 优先结束捕获，不穿透到查找与比较；捕获转移不释放其他控件的捕获。隐藏、禁用、对应工具区折叠及 DPI 改变清除在途拖动，不新增定时器、线程或 Git 查询。
- 当前文件查找通过 Scintilla 只更新选择、匹配高亮和滚动，查找条固定在正文顶部并占用一行，不请求正文焦点；原生输入 subclass 记录组词状态，主消息循环先把组词按键交还输入控件，再处理全局关闭。输入改变后自动定位首项，`Enter`/`Shift+Enter` 前后定位并显示当前项/总数，`Esc` 收起查找条。查找开关与导航沿既有焦点序列移动；当前正文引用、查询及三个开关未变时复用匹配位置与计数，不复制正文；高亮按时间片写入，新查询、隐藏或销毁取消旧批次。查找图标集中在 `NativeTheme.FindIcons.cs` 并复用现有 GDI+，不增加依赖、进程或线程。
- 普通文本查找计数与双向定位统一使用 `Ordinal`/`OrdinalIgnoreCase`，全字边界统一为字母、数字类别及下划线；普通定位不转成 Regex，避免与正则大小写折叠不同导致数量为零却能定位。被全字条件拒绝后只前移一个字符，避免漏掉重叠的有效候选；导航复用已加载字符串，不增加结果缓存。HTML 查找稿使用固定正文和临时 Worker 验证操作，关闭、隐藏、换查询和超时均终止 Worker 并回收 URL；浏览器与 .NET 正则引擎不同，HTML 验证不作为全部搜索语法等价的证据，也不成为正式应用依赖。
- `NativeDocumentView.Find.cs` 使用 .NET 线程池处理所有正则、至少 100000 个 UTF-16 字符的正文或至少 1024 个字符的查询；计数和定位分别串行，旧查询取消后在下一次扫描前检查，不增加专用线程或进程。后台扫描只读取已加载字符串，不读写控件；结果通过文档私有 Win32 消息投递到创建控件的线程。任务身份、正文引用、查询、开关、显示与销毁状态全部有效时才应用，150ms 加载提示也使用相同校验；无需依赖调用方的同步上下文。成功、错误、关闭与取消均结束临时延迟并释放取消源，正则的单次匹配最多等待既有 250ms 超时返回，UI 不同步等待。格式化字符串由文档复用，后台不复制全文或保存匹配列表；连续导航只排队方向。
- 查找输入边框由正文顶部查找条绘制，原生 Edit 不带系统边框，按实际字高居中并保留同一 HWND。正文起点计算必须包含可见查找条的高度，Markdown 对照分隔线的绘制和拖动命中使用同一起点，不能伸入查找条。获得或失去焦点只使查找条失效重绘，留白命中通过既有查找条 subclass 转交焦点，不重设查询和选择；销毁文档时一并移除输入与查找条 subclass。主题边框不使用覆盖窗口或额外常驻资源。
- 查找输入 subclass 在 `WM_IME_STARTCOMPOSITION` 时取消未完成扫描与导航队列；期间 `EN_CHANGE` 只清除旧数量，不开始查询。`WM_IME_ENDCOMPOSITION` 先交原生 Edit 接纳最终文字，再解除组词状态并查询；失焦收尾复用保留正文位置的路径。取消组词复用原查询结果，重复最终文字通知不清除匹配位置；隐藏与关闭清除组词状态，旧结果仍受任务身份和可见性约束。HTML 视觉稿通过 `addEventListener` 绑定组词事件，关闭或重新绑定时用 `AbortController` 解除旧监听，不增加正式应用依赖或后台资源。
- JSON 视图保留当前 `JsonDisplayResult`，正文与查找复用同一份格式化字符串；只在源内容变化后重新格式化，替换或销毁正文时释放该结果。查找计数缓存只引用该字符串，不另外复制全文。切换原文/格式化时清理旧匹配位置并按新显示文本计数，同一模式重复操作不重置位置；不缓存历史版本或解析树。
- 图标按钮继续由 owner-draw 绘制可见图形；产品规格内已有功能图标必须按 PyCharm 2026.2.1 New UI 对应图标逐像素复原其轮廓、比例、线宽、填充、位置、颜色和状态。实现使用项目内自绘等效图形，不分发 JetBrains 官方图标、字体、商标或产品标志；Augit 自有品牌标记是唯一品牌例外。统一 Tooltip 层通过 Windows `IAccPropServices` 为控件设置 `PROPID_ACC_NAME` 动态辅助功能注释，使屏幕阅读器获得与悬停说明一致的中文名称，同时不改变可见文字。该能力使用 Windows 自带 Oleacc，不引入第三方依赖或常驻进程。
- Diff 的单双栏与忽略空白图形统一由 `NativeTheme.DiffIcons.cs` 绘制，工作区和历史/引用比较只提供模式与状态颜色；复用已有 GDI+ 细线与圆弧入口，逐次释放笔和图形对象，不依赖当前 GDI 画刷或字体，不引入依赖、线程和资源缓存。图形几何及参考证据归设计系统管理。
- Diff 分段组的边界、背景和键盘焦点绘制由 `NativeTheme.DiffToolbar.cs` 统一；父窗口绘制外框，原有两个 owner-draw 按钮分别接收输入并绘制选中态。工作区与历史/引用比较复用同一入口，不新建控件层或常驻资源；Enter 只在当前可见、启用且获得焦点的按钮上转换为原生命令，Space 保留原生按钮处理。
- `NativeDiffFileHeader` 统一工作区和历史/引用比较的只读身份绘制、文字度量与单双栏排布。显示模式就绪后仅重排文件信息和正文；请求中保留已显示模式，摘要按所选模式显示，不通过重新布局主窗口或重查 Git 更新文件信息。复用既有静态控件和 GDI+，不引入新依赖或常驻资源。
- `NativeTextPrompt` 共用原生模态焦点与遮罩，以顶层 HWND 为 owner；字体、DPI、颜色及按钮绘制复用 `NativeTheme`。窗口只返回文本，由原调用方校验和执行动作；键盘处理限定在当前窗口，输入法组词期间不抢占确认与取消。关闭释放窗口、Tooltip、输入 subclass 和画刷，嵌套消息循环保留主循环退出请求；不增加进程、线程或常驻缓存。
- `NativeStashDialog` 以 `IGitWorkspaceStateService.StashWithOptionsAsync` 执行现有本机 Git 操作；后台完成仅投递私有窗口消息，界面线程完成状态切换和关闭。销毁先取消并清除结果槽，再销毁窗口；未完成取消源由服务调用收尾释放。成功先结束运行态再关闭，失败保留输入；正文使用单个原生滚动容器，标题与动作固定。原生自动复选框保留键盘、状态与辅助功能语义，绘制复用统一图形；不增加运行时依赖、计时器或专用线程。
- `NativeStashManagerDialog` 使用左侧 Stash 列表、右侧 `NativeDialogBody` 详情视口和固定标题／工具栏／底栏；右侧标题、元数据、动作、变化文件与错误说明按当前界面实际行高测量，详情获得焦点时由正文视口自动滚入可见区域。所有操作按钮复用 `NativeDialogActionButtons` 的悬停、焦点、禁用和危险状态，底部不绘制无功能帮助占位；关闭时先释放视口、按钮状态和 GDI 资源，避免迟到结果回写已销毁控件。
- `NativePushDialog` 的预览和推送结果通过私有窗口消息在 UI 线程接纳，关闭时取消任务并清空待接纳结果；执行中的取消源由后台收尾释放。成功先结束进行态再关闭，取消结果不能被晚到成功改写。提交列表使用原生 owner-draw 固定行高及统一自绘勾形，既有 subclass 负责局部悬停、失焦选中色和销毁清理，不以字体字形代替图标。正文和分隔线共用同一高度预算，限高时扣除无远端标签行；详情文字按宽度缓存测量并局部滚动，不移动标题或底栏。没有新增运行时依赖、窗口、专用线程或应用计时器。HTML 仅模拟状态，关闭回收模拟延迟、监听及背景禁用状态，不接入 Git。
- `NativeRemoteDialog` 作为 Push 的嵌套模态窗口复用同一 UI 线程消息循环；远端读取、添加、更新和删除的后台结果通过窗口私有消息接纳，并以取消源、窗口关闭状态和操作身份校验。关闭、销毁或用户重新输入时清空待接纳结果，晚到结果不得更新控件或外层 Push；关闭时转发外层 `WM_QUIT` 退出码，恢复 Push 的焦点上下文。输入草稿保留在窗口生命周期内，详情滚动与字段布局不重建主窗口，不增加进程、专用线程或运行时依赖。
- `NativeCloneDialog` 复用现有 `IGitRepositoryService.CloneAsync`，表单校验和 Git 查询完成均在窗口所属线程接纳；后台只投递私有完成消息。取消先请求本机 Git 停止，宿主销毁后清除结果槽并拒绝晚到结果；失败保留 URL、目录和浅克隆深度，成功返回仓库路径并关闭。字段和错误说明按实际字高布局，单个原生正文容器负责滚动与焦点可见性，标题和动作固定；错误按内容与宽度缓存度量，滚动不重查 Git。Tab、输入法组词、标题关闭和下拉框沿原生控件语义处理，销毁解除所有输入 subclass 并释放 Tooltip、画刷和取消源，不增加依赖、常驻线程或 Git 平台接口。
- `NativeModalScrim` 复用原有分层子窗口，通过宿主的窗口子类回调跟随客户区大小；尺寸相同不重复布局。遮罩主动关闭或宿主先销毁均解除回调并清除实例登记，构造失败也立即清理。保留系统透明度合成，不截取或缓存主窗口图像、不增加线程或位图缓存。
- 远端管理右侧详情由一个带原生滚动条的 Win32 子窗口裁切；标题栏、左侧列表和底部关闭保持固定。字段及动作复用原有控件，通知转发给原对话框；焦点进入时只调整详情偏移，不查询 Git 或重建主窗口。字宽在字体/DPI 改变时度量，错误换行按文字和视口宽度缓存，滚动复用结果；所有 subclass 随控件销毁移除，不引入依赖、线程或位图缓存。
- `Augit.exe` 嵌入显式 Win32 应用清单，以普通用户权限运行，声明 Windows 10/11 兼容、长路径感知和 ComCtl32 v6；不因原生外壳请求管理员权限或引入额外运行时依赖。
- Scintilla 只分发官方 x64 `Scintilla.dll`，大小为 `1128808` 字节，SHA-256 为 `D30C0D1676AFDFFB42A8322FC52EC0BCC03DDF54F05249B566365DABC8DC50ED`；不分发、不加载 Lexilla，也不启用语法高亮。选择它是因为 Windows RichEdit 无法同时稳定满足行号、空白符显示、换行、双栏 diff 和冲突编辑，自研 DirectWrite 文本控件会显著做重；许可证为 Scintilla 宽松许可证。若原生系统控件以后能在相同性能下完整替代这些能力，应移除 Scintilla。
- Scintilla 正文的深色滚动条交界空角由轻量 `NativeScrollBarCornerTheme` 按当前主题补画；它只处理非客户区交界矩形，不重绘滚动条、正文或输入，且在 HWND 销毁时释放 subclass 和颜色登记，不增加进程、线程或运行时依赖。
- PNG、JPEG/JPG 和 BMP 使用 Windows Imaging Component 解码，首版不引入额外图片解码依赖，不支持 GIF 和 WebP 预览。
- 图片滚轮输入由 `NativeImageView.Input.cs` 累计 Win32 的 120 单位档位，Ctrl 多档缩放先算最终比例再发出一次视图通知；平移保留整数除法余量并处理 `WM_MOUSEHWHEEL` 的正向向右语义。隐藏、模式切换、工具按钮与图片替换清除余量，复用现有绘制消息，不增加依赖、窗口、线程或计时器。HTML 视觉稿把 DOM 像素/行/页单位换算为常规 40px 滚轮档位，仅用于浏览器输入适配。
- WIC 直接把预乘 BGRA 写入唯一原图 DIB，避免托管像素数组及中间原生缓冲的双重复制；使用 Windows AlphaBlend 合成透明度。棋盘格复用小型图案画刷，图片绘制复用视口大小的 32 位缓冲，完整帧一次呈现，尺寸变化才重建，隐藏时释放帧缓冲、销毁时释放控件持有的 GDI 资源。帧内存约为视口宽×高×4 字节；后台采样缓存及原图租约另见下文，无新运行时依赖或专用线程。
- 图片解码使用线程池，全进程共用一个异步串行闸门；已取消的排队请求不进入 WIC。WIC 一次原生解码不能强行中断，执行中的请求在返回后检查取消并释放位图，界面不等待该过程。完成和 150ms 延迟提示通过文档私有窗口消息分发，不依赖测试或调用方的同步上下文；请求身份、结果接收及销毁由同一锁保护，未分发的结果也随关闭释放，不向隐藏文档转移焦点。闸门不创建专用线程或进程，延迟任务随解码结束取消。
- 图片平滑采样使用线程池和独立的全进程串行闸门，通过既有 GDI+ 包装预乘 DIB，后台只生成当前可见区域的透明图像。缓存就绪前界面使用快速采样，就绪后通过图片窗口消息原位替换；后续绘制只合成缓存，100% 及放大沿用 AlphaBlend。缓存最多为视口宽×高×4 字节，缩放、平移或替换使旧请求失效，隐藏及关闭释放缓存；原图通过短期引用租约保留到原生计算退出，避免 UI 关闭等待或后台读取已释放像素。图形上下文和图片包装在后台操作结束时释放，不保留整幅缩放副本或增加运行时依赖；GDI+ 初始化通过同一锁完成。
- Markdown 与终端按需创建 WebView2 原生子窗口和 `CoreWebView2Controller`，普通浏览和启动路径不加载 WebView2。
- Markdown 预览创建受可取消的串行创建闸门保护；隐藏标签取消未完成初始化，避免多个标签争抢 WebView2 和产生无效浏览器进程。
- Markdown 的原文、预览和对照共用文件标签与已创建的浏览器；切到原文或后台仅隐藏完成的预览，关闭文件或主窗口才销毁会话。模式切换不重复解析和启动，隐藏标签的外观与正文变化只标记待更新，显示后再渲染。原文复用 Scintilla 并保留选择和滚动。
- Markdown 对照拖动按有符号 Win32 客户区坐标解码，记录按下偏移，并以夹紧后的实际栏宽去重；无可用宽度时不改比例。拖动只重新排布正文与局部预览反馈，不重排工具栏和查找条、不重渲染 Markdown 或调用 Git。捕获转移只清理自身拖动状态，松开、Esc、系统取消、禁用、切换模式、隐藏和销毁只释放自身持有的捕获，不释放新控件的捕获；主消息循环在查找关闭前接纳拖动 Esc。不新增依赖、线程、窗口或计时器。
- `MarkdownPreviewRenderer` 在线程池解析与改写资源，通过可取消串行闸门限制并发；Markdig 单次同步解析不可中断，进入和退出解析阶段均检查取消。文档请求按版本和可见性接收，预览更新串行；现有 WebView2 只通过官方脚本接口替换受控页面的正文与样式并恢复滚动，不注册宿主对象或文件/Git 能力。DOM 就绪后先显示正文，合法本地与 HTTP/HTTPS 图片在自有容器中独立显示加载、成功或失败反馈；替换正文后重新绑定图片状态，旧图片事件不能更新当前正文。加载超过 150ms 显示局部提示，渲染失败保留旧内容。无新增运行时依赖、专用线程或常驻辅助进程。
- Markdig 禁用 Markdown 原生 HTML，HTML 标签转义为普通文本；渲染模板由 Augit 控制，不引入 Sanitizer。
- 终端通过 Windows ConPTY 连接 shell，WebView2 内使用 xterm.js `6.0.0` 负责终端显示、ANSI 控制和键盘交互，并使用 `@xterm/addon-fit` `0.11.0` 同步行列尺寸。两者均为 MIT 许可证，发布产物只包含锁定的 JavaScript、CSS 与许可证文本，不引入 Node.js、前端构建链或常驻进程；npm 包 SHA-512 完整性分别为 `TQwDdQGtwwDt+2cgKDLn0IRaSxYu1tSUjgKarSDkUM0ZNiSRXFpjxEsvc/Zgc5kq5omJ+V0a8/kIM2WD3sMOYg==` 与 `jYcgT6xtVYhnhgxh3QgYDnnNMYTcf8ElbxxFzX0IZo+vabQqSPAjC3c1wJrKB5E19VwQei89QCiZZP86DCPF7g==`。自行实现终端协议会显著做重，只有平台以后提供兼容且更轻的稳定原生终端控件时才移除这两项依赖。
- Git 通过独立进程调用用户设置或系统 `PATH` 中的本机 `git.exe`；搜索按需调用随程序附带的 `rg.exe`。
- 提交面板的文字尺寸由 `NativeGitPanel.Layout` 在字体或 DPI 改变时度量并缓存，窗口缩放复用字宽；提交勾选、输入和反馈不触发度量或 Git 查询。Changes 行高按实际字体设置，修改外观后恢复首个可见项。窄栏动作换行和空态说明收纳复用现有子窗口，不创建额外线程、窗口或常驻依赖。

## 2. 模块边界

- 主框架的左侧全局入口、项目标题与终端标题按钮共用标题栏已有的窗口内鼠标跟踪与 Enter 转交，不为各组重复维护线程或计时器。绘制按各自背景与激活状态区分，只有旧、新目标局部失效；终端控件销毁解除 subclass，跟踪对象随主窗口销毁清空。终端标题 Tab 在原有三个动作内循环，不拦截 WebView2 正文输入；标题布局按字体和名称测量，字体改变复用现有控件，不重新创建 Shell 或浏览器。Tooltip 由终端面板持有并随关闭释放。

- 文档按钮的悬停由其所属 `NativeDocumentView` 持有一个 HWND 和 `TrackMouseEvent` 跟踪标志；按钮 subclass 以文档 HWND 找回所属实例，禁止跨文档传递悬停。同一按钮移动不重新失效，旧、新目标只局部重绘；隐藏文档、控件禁用、移出和销毁清除，所有按钮 subclass 在原生销毁时解除。绘制使用局部 `DrawItem` 状态，不改写系统传入的结构或文档数据；焦点复用 `NativeTheme.DrawToolbarFocus`，不增加窗口、计时器、线程、缓存或运行时依赖。

- 标题栏 owner-draw 按钮通过限定在本主窗口的 subclass 与 `TrackMouseEvent` 共用一个悬停 HWND；不依赖系统是否提供 `ODS_HOTLIGHT`，只有目标变化才使旧、新按钮失效。隐藏、禁用、移出及销毁取消跟踪；控件销毁解除 subclass，主窗口注销前清空悬停。Enter 在核对焦点、可见/启用和修饰键后转交原生按钮点击，空格保留原生处理；不新增控件、计时器、线程、Git 查询或运行时依赖。

- 主消息循环按消息目标 HWND 分配键盘输入：主窗口及其子控件进入应用快捷键，正文顶部查找条继续共用既有搜索处理，分支弹层只共用 Tab 导航，其余独立菜单或窗口交给自身消息过程。菜单 Esc 不得先触发后台正文查找条的关闭。右键菜单和工具栏弹层在销毁前记录前台归属，只有仍属于本应用时恢复原控件焦点；失活立即关闭且不抢回焦点。不增加线程、计时器或依赖。

- 主窗口关闭统一由 `WM_DESTROY` 完成一次资源释放、实例注销和消息循环退出；`Close` 与 `Dispose` 的重复调用只做幂等返回。若宿主已提前销毁原生句柄，`Dispose` 仍负责兜底释放托管资源；销毁过程中不再接受新的关闭请求，异步回调只能丢弃结果，不能访问已销毁控件或重新创建标签。该保护不改变切换工作区时的正常资源释放，也不增加线程、窗口或运行时依赖。

- `Augit.Core`：工作区、文档分类、UTF-8 校验、显示规则、Git 状态语义和操作会话等稳定规则，不依赖 WPF、文件系统或进程类型。
- `Augit.Infrastructure`：本地文件读取与监听、Git、ripgrep、ConPTY、设置持久化和外部程序适配。
- `Augit.App`：原生 Win32 界面适配、窗口生命周期和界面状态，不承载文件格式或 Git 业务规则。

Git 能力必须拆成窄而稳定的接口，例如仓库识别、状态查询、提交选择、历史读取、引用管理和操作会话。冲突解决单独建模，不能让普通文档查看接口获得保存能力。

## 3. 只读与写入边界

- 普通文档接口只暴露读取结果，不暴露保存、替换或写流能力。
- JSON 格式化、Markdown 渲染、换行和空白符显示都只生成内存中的显示结果。
- Scintilla 使用公开的可见行宽度跟踪 API，初始滚动宽度为 1px，正文替换及字体变化时重新起算，不为确定全文件宽度扫描全部行。文档控件的 subclass 在原生绘制完成后，仅当度量或正文版本变化时提交一次滚动范围并收回越界横向偏移；末尾保留 1 物理像素余量，稳定绘制不增长范围、不触发全局布局。每个 HWND 一条登记，原生销毁消息解除登记；不新增线程、计时器、进程或正文副本。普通正文、比较正文与三栏结果区仍共用该控件，显式禁用的比较行号滚动条保持禁用。
- JSON 错误位置将解析器的 UTF-8 字节列转换为从 1 开始的 Unicode 标量列；只扫描至错误行和列，不生成额外全文副本。文档内错误条使用原生只读提示按钮及现有 Scintilla 行定位，按正文有效性禁用格式化入口；错误变化仅布局当前文档，焦点与后台查找沿用现有上下文保护。无新增运行时依赖、线程或进程。
- 文档工具栏使用现有子窗口与字体度量：图片文字按实际字宽分配，目标路径和 JSON 错误共用换行高度计算；仅重排当前文档，不重新加载正文或解码图片。键盘导航显式按可见动作顺序排列，Enter 复用原生命令；图片比例没有变化时不重复更新 Tooltip 文本。无新增依赖、线程或常驻服务。
- 用户主动执行 Git 操作时，由本机 Git 进程修改索引、引用或工作区。Augit 不绕过 Git 直接模拟 checkout、merge、reset 等文件写入。
- Git 写操作必须通过明确的应用用例执行。命令失败时只在当前操作界面临时显示经过脱敏的命令结果，不建立 Git Console、操作历史或持久化日志。
- 只有冲突解决用例能把用户直接编辑的最终结果写入文件；写入前必须校验操作状态、路径和文件版本。
- 外部工具改变文件或 Git 状态时，界面刷新读取最新磁盘事实，不把缓存冒充真实状态。

## 4. 文件与预览安全

- 文本读取在分配大缓冲区前检查文件长度，只接受有效 UTF-8，可识别并去除 UTF-8 BOM。文件分类先识别受支持图片，再匹配其他已知二进制签名和 NUL 字节，其余内容执行严格 UTF-8 校验。
- 目录符号链接和目录联接不递归。普通文件符号链接显示解析后的目标路径；本机固定磁盘上的工作区外目标允许只读访问，网络、远程、失效和循环目标拒绝读取。
- 图片读取在调用 Windows Imaging Component 解码前检查 25 MB 文件上限，并在分配完整像素缓冲区前检查 2500 万解码像素上限。
- Markdown、JSON 和冲突文本在解析或构建显示模型前同样执行 10 MB 文本上限与严格 UTF-8 校验；不符合冲突文本边界的文件只允许通过本机 Git 选择两侧版本或交给外部工具。
- Markdown 本地资源在规范化并解析符号链接后必须仍位于工作区内；越界资源不交给 WebView2。
- Markdown 只把禁用原生 HTML 后的受控渲染结果交给 WebView2；标题锚点在预览内处理，工作区相对文件链接交回 Augit 只读导航。
- Markdown 标题使用 Markdig 的 GitHub 标识规则，保留中文并为同名标题增加唯一后缀；相对 URL 先分离查询与锚点，再解码文件名，允许工作区内包含转义井号的真实文件名。资源无效时只替换对应图片或链接，不影响其余正文。
- 远程图片只允许 HTTP 和 HTTPS，并且只在用户打开 Markdown 预览时加载；正文 DOM 就绪不等待远程图片，图片失败只替换对应容器并显示原因。HTTP、HTTPS 和邮件链接交给系统，绝对本地路径、越界路径和未知协议阻止处理。
- WebView2 以原生子窗口为宿主，使用独立、可释放的环境和控制器，不注册文件或 Git 能力。

## 5. Git 与外部进程

- 提交图在历史快照变化时计算，绘制回调只消费已有布局；重复选择、焦点变化、滚动和无变化刷新不重算父关系。提交图每行使用一个 GDI+ 绘图上下文，按需复用最多四种画笔并保持原连线顺序，避免交叉点覆盖关系改变；常规线段缓冲使用栈，复杂行临时租用数组并立即归还，原生画笔和上下文在本行结束后释放。历史列表的最小可读宽度使用已有图形宽度与文字度量，横向滚动使用原生 ListBox，不增加控件框架、依赖或后台进程。
- 历史查询在启动时捕获页码、筛选及取消令牌，结果接纳同时验证请求版本和取消状态。已加载页码只在成功后推进，重新读取多页时根据每页的结束标记停止并按哈希去重。追加期间保留可浏览列表，短暂关闭重绘只包围结果应用阶段；完成后恢复当前提交、顶部锚点及横向位置。文件历史返回先恢复普通布局，再应用原上下文的滚动位置；历史查询的浏览例外不放开 Git 写操作期间的动作限制。
- 文件历史返回快照以工具窗口模式判定是否首次进入，不能以路径筛选是否为空判定；复用变化文件视图快照保存选择、折叠与顶部锚点，同时保存筛选输入草稿和详情显隐。恢复时相同历史快照跳过列表与图形重建，差异优先使用既有增量更新；详情未完成时按恢复后的提交重新读取。文件历史预览以提交/路径去重，使用独立可取消请求和版本校验；改选、隐藏、返回和销毁取消，取消源由查询方法收尾释放，150ms 提示与查询共用生命周期。不增加依赖、常驻线程或进程。提交行作者、日期和标题共享一次字体度量；作者/日期列不低于视觉稿基线，标题保留最小辨认宽度，内容不足时由列表自身横向滚动承载，不修改提交身份或预览请求。字体、DPI 或快照变化才重新度量，不在每行绘制时重复测量。
- 历史行使用内容坐标绘制，横向平移交由原生 ListBox 的绘图上下文处理，不能在 owner-draw 中再次扣除滚动值。画面回归通过 PrintWindow 捕获列表并直接读取 DIB 的客户区像素，同时检查标题和元数据，避免只验证滚动条位置而遗漏文字移出视口。
- 历史字号适配复用 `NativeTheme.UiLineHeight` 的字体度量缓存。应用外观时重新设置三个 owner-draw 列表的实际行高，更新局部布局后恢复各自首个可见项与历史横向位置；变化文件滚动条及分页触发距离使用实际行高。标题、标签和取消按钮按真实字体测量；Git 标题由布局直接定位到 12px，绘制不再叠加内距，日志与文件历史标签共用文字内距和边框预算。局部布局不重查 Git，不引入额外控件、常驻进程或字体缓存。
- 历史工具栏 Enter 由主窗口消息循环转交面板，核对当前焦点、可见/启用状态及修饰键后复用原生按钮命令；Space 继续沿用按钮消息。工具栏和筛选组在局部布局前记录焦点，隐藏目标后只在同组可见动作间恢复，列表与输入焦点不参与转移。图标、筛选和溢出弹层复用已有焦点框绘制，不增加窗口、计时器或 Git 查询。
- 提交详情复用原生 owner-draw 子窗口与系统滚动条，正文不再截为 1200 字符。系统 GDI+ 在后台排版为通常不超过八个显示行的块，缓存仅保存原字符串范围、宽度和位置，不复制块正文；滚动二分定位可见块，不把整个长段落交给绘制函数。沿用已加载的系统 GDI+，没有新增依赖或常驻线程。每次排版使用独立字体和内存 DC，结束或取消后立即释放，不能跨线程借用界面字体句柄。
- 详情排版先交付首块以显示正文，再交付完整滚动范围；连续宽度、字号或提交变化取消旧排版，单面板的任务顺序接续，结果按版本接纳。滚动条出现后按实际客户区宽度排版。排版期间的 End 在完整结果到达后定位末尾；已有内容重新排版时保留原滚动位置。滚动命令入口仅对行、页、滑块、首尾定位更新导航状态，`SB_ENDSCROLL` 等非导航通知直接返回，不清除末尾意图或滚轮余量，也不重查 Git 或排版。面板隐藏时取消尚未结束的排版，重新显示按需恢复；窗口销毁时解除 subclass 和实例登记、取消任务、丢弃待接纳结果。文件历史快照继续记录详情位置。
- 排版与绘制期间固定原字符串，结束立即解除；文字块累计位置使用双精度，转换为视口相对坐标后再交给 GDI+，避免长正文下单精度累计高度漂移。字形由客户区裁切，不按每个浮点文字块边界裁切。无换行长单词、中文、组合字符和空白必须分别回归；极端零宽字符序列可能扩大一次系统排版的输入，单次系统调用不能中途抢占，这类异常输入和全应用正式性能矩阵仍需独立验收。
- 设置预览、取消恢复与最终确认都向现有 Git Changes、历史和比较视图传入最新设置，重用面板、提交草稿、比较正文和选择。只有 Git 可执行路径改变才重新建立 Git 面板及其服务；普通字体或主题确认不销毁历史上下文，不重复读取已有比较。

- Git 定位顺序为用户设置路径、系统 `PATH`；不从仓库内寻找或捆绑 `git.exe`。Git for Windows 2.40 是整个 Git 模块的最低版本，缺失或低于该版本时禁用 Git 面板和操作服务，但保留 Git 路径设置入口。
- 每条 Git 命令明确以当前工作区为工作目录，继承本机 Git 配置、凭据助手和 SSH 环境。
- 文件复选提交完全使用本机 Git：先对选中的未跟踪文件执行 `git add`，再使用 `git commit --only` 和选中文件路径提交磁盘完整内容；不建立 Augit 自有索引事务，不把未选中的既有暂存项带入提交。
- Conventional Commits 1.0.0 兜底校验属于 `Augit.Core` 规则，只处理用户手工输入的 Commit 和 Amend 信息；仓库规则和 Git 自动生成的信息绕过该兜底规则，但仍完整执行本机 hooks。
- Git 状态以 HEAD、索引和工作区的最新本地事实为准；远端状态只在用户主动 fetch 或 pull 后更新。
- 文件监听和 `.git` 状态监听事件合并刷新，目标是在 500 毫秒内反映本地变化，不通过持续扫描或后台 fetch 实现。
- Changes 状态刷新优先核对当前加载请求的路径、忽略空白选项与输入版本；只有路径和选项匹配时才使用已有正文的版本。新文件加载期间暂留的旧正文不能触发新文件重载。状态循环仅发起必要的 Diff 更新，不等待其查询或排版；Diff 继续通过自身请求版本、取消及局部反馈完成，列表更新不会被慢正文阻塞。
- 所有外部进程都支持取消、输出边界、退出码和稳定错误结果；认证信息和敏感环境变量不得进入界面错误输出。本地只读 Git 查询设置 30 秒自动超时，网络与 Git 写操作不设置自动超时，只响应用户主动取消；取消后重新读取仓库实际状态，不自行删除 Git 锁文件或伪造回滚结果。
- Reset 的目标解析保留完整命令结果：`rev-parse --verify --quiet` 的目标无效退出码与取消、超时、启动失败分开处理。后者保留原失败类型和脱敏原因，并使用不继承取消令牌的只读查询获取实际状态；目标解析失败不进入 `git reset`。
- Reset 窗口通过现有 `IGitWorkspaceStateService` 执行动作，后台只投递私有完成消息，窗口线程接收结果；关闭和宿主销毁取消请求、清空结果槽，晚到结果不访问控件或状态提示。取消请求不覆盖服务返回的真实成功结果，不伪造回滚。失败保留原输入与模式；输入法组词和展开的模式列表优先处理自身按键，嵌套消息循环转发退出码。
- Reset 与回滚按钮共用限定在各自窗口的 subclass 跟踪悬停，焦点由真实 HWND 决定；隐藏、禁用、移出和销毁解除跟踪，不依赖 `ODS_HOTLIGHT`。回滚 Tab 序列展开现有比较视图的工具栏与可见只读正文，Enter 转交对应动作，窗口仍只返回确认选择，不执行 Git 写入。无新增依赖、线程、计时器或常驻窗口。
- Reset 与回滚共用 `NativeDialogBody` 原生正文子窗口负责裁切、纵向滚动与字段焦点可见性，标题和底栏仍由各窗口持有；换行度量按宽度、字体行高和当前文字缓存，滚动只复用布局，不重查 Git。Reset 初次完成字段和滚动条布局后按 `GetComboBoxInfo` 的实际文字区域补足宽度，不猜测系统箭头尺寸；状态更新只重排正文。回滚复用现有比较 HWND 和只读正文，正文滚轮保留比较自身语义；销毁正文解除所有 subclass，窗口销毁链释放子 HWND。未新增运行时依赖、线程或常驻进程。
- 原生选择框的收起表面统一由 `NativeComboBoxTheme` 绘制：正文表面、圆角边界、焦点边界、禁用文字和 V 形箭头一次性覆盖系统客户区；下拉列表仍交给 Windows owner-draw 和键盘语义。组件按实际 `ComboBox` 客户区和选中项重绘，选择项变化、展开状态、焦点、启用状态和销毁均清除或更新登记，不轮询、不创建计时器；已有父表单外框的 Clone、Stash、Reset 传入父框模式，避免双重边框。
- 图形 Git 命令出现交互输入需求时停止执行并返回稳定原因，不生成可复制命令，也不与内置或外部终端建立重试流程。
- merge、rebase、cherry-pick 和 revert 的操作会话以 Git 元数据目录中的真实标记、未合并索引项和暂存差异为准；Continue、Skip 和 Abort 只在当前 Git 状态实际支持时显示，不能由界面缓存推断成功。
- Smart Checkout 只使用本机 Git 创建带唯一 Augit 标记的临时 stash，完成切换后再由 Git 恢复；恢复冲突保留 stash 并进入统一冲突流程，重新打开窗口后可从 stash 标记恢复会话，不建立 Augit 自有索引事务。
- 冲突服务单独读取 Git 索引的 stage 2 和 stage 3 作为左右两侧，普通文档服务不参与写入。只有不超过 10 MB、无二进制签名和 NUL 字节的有效 UTF-8 三侧内容进入三栏编辑。
- 冲突结果保存前重新校验规范化仓库内路径、未合并索引项、Git 操作类型和工作文件的长度、修改时间及 SHA-256；写入同目录临时文件后原子替换并调用 `git add`，任何失败都返回最新实际状态，临时文件在操作结束时删除。
- 冲突标记解析按 UTF-16 文本的一次线性扫描读取行边界，只保留有效块的起止位置及当前侧、可选祖先和合入侧字符串；不为整份文本创建逐行对象。解析在进入、每 256 行及返回前检查取消；冲突服务的加载、重载与保存校验传入所属请求的取消令牌。单条长行查找和块字符串提取不能中途抢占。
- 三栏任一侧至少 100000 个 UTF-16 字符时，在界面线程捕获结果快照，线程池串行完成解析、侧内容匹配及行区间计算；连续编辑取消旧版本，关闭或重新载入清除待接纳结果。仅完全相同的初始正文复用服务返回的块，接受和编辑后的正文重新解析。结果通过解决器私有窗口消息回到创建控件的线程，不依赖同步上下文。行背景以最多 64 行一组、约 8ms 一片更新，立即续调度并交还消息循环；每片核对窗口及请求身份，不重复构建逐行索引。计算期间保留正文和关闭入口，接受、导航与保存等待当前版本就绪；异常保留正文并允许重新检查。外部更新的重新载入或保留选择继续有效，晚到结果不能清除对应提示。关闭释放计时器、待分发结果及控件，计算退出释放取消源；不新增依赖、专用线程或进程。捕获/替换 Scintilla 正文仍是同步原生调用，不能由这条后台链路推导所有接近 10 MB 的编辑、接受及关闭时延已完成正式验收。
- 三栏结果区使用唯一解除只读的 Scintilla 控件；左右两栏始终只读。中央显示层隐藏 `<<<<<<<`、`|||||||`、`=======` 和 `>>>>>>>` 所在的标记行，但底层正文仍保留完整 Git 文本，保存、撤销和 UTF-8 范围操作不使用显示层的偏移。正文替换、接受、撤销、重载和主题更新后按当前解析块重新设置隐藏行；隐藏只调用 Scintilla 的行可见性接口，不插入空行或创建正文副本。工作文件与 Git 元数据监听分别同步外部内容和已解决状态，存在未保存内容时必须由用户选择重新载入或保留当前内容。保存期间共享取消令牌并冻结所有动作；失败或取消后按当前未处理冲突数恢复接受/导航按钮，不能把无效动作重新启用。
- 接受冲突块使用 Scintilla 公开的目标范围替换与撤销分组接口，只替换该块的 UTF-8 字节范围，每次接受独立成一步，保留此前手工编辑。编辑入口拒绝只读控件及非完整字符边界；保留块外选区对应正文、选择方向及水平位置，冲突导航继续按当前块对齐三栏。未保存状态使用控件保存点；用户选择保留外部版本时另记磁盘差异，撤销回旧保存点不能绕过外部变化保护。不复制整份正文到每一步撤销记录，不增加运行时依赖或后台资源。
- 三栏结果变更使用结果文本快照和解析块集合，接受、导航、保存校验与延迟装饰在同一版本内复用；重复导航不重新扫描或重建相同背景标记。三侧冲突块按出现顺序推进 UTF-16/CRLF 位置和行号，避免每个块从全文开头重复计算；主题变化只更新已有标记颜色。滚动同步为内存中的虚拟行坐标映射：每个冲突块占用三侧行数的最大值，块间上下文按相邻块区间线性映射，空侧钳制到块起点；映射只改变各 Scintilla 的可见首行，不写入正文、撤销记录或保存内容，并在同步保护期间丢弃回调，避免循环。长短差异、空侧、块前后上下文和大正文映射必须由算法及原生交互回归覆盖。
- 冲突模态循环在字符翻译前处理结果区的撤销/重做快捷键，仅接受当前聚焦结果 HWND 的 Ctrl+Z、Ctrl+Shift+Z 与 Ctrl+Y，Alt 组合交还正常输入；保存中消费动作但不修改正文，避免快捷键被翻译成控制字符。该接线是 Augit 自身输入适配，不作为 PyCharm 直接操作证据。
- 冲突动作按钮复用原生 Button 与局部 subclass 跟踪唯一悬停目标，焦点独立绘制，不依赖 `ODS_HOTLIGHT`。同一目标内移动不重复失效，隐藏、禁用、关闭及原生销毁解除跟踪；不增加窗口、计时器、线程、依赖或 Git 查询。
- 三栏滚动区间使用显示行坐标：中央隐藏标记从滚动区间长度与后续起点中扣除，原文行号继续单独用于着色和 UTF-8 范围操作。块间上下文按三侧间隙的最大长度建立虚拟区间，正反向映射都从上一块末尾计算，避免落入下一块的负偏移。仅 `SCN_UPDATEUI` 的纵向滚动通知驱动同步，不反写用户正在滚动的来源栏；导航批量设置三栏首行时保持同步保护。原生回归直接通过 Scintilla 的显示行到原文行转换核对屏幕首行，不以同一虚拟映射算法生成断言。
- 三栏短侧通过 Scintilla 公开 annotation 接口补齐行间展示留白，锚点使用原文行号，合并同一锚点的多段留白；中央锚点跳过隐藏标记。留白沿用默认等宽样式，不写入正文、撤销或保存点。空片段先依据前置公共上下文确定所在行，避免误挂在上一冲突末尾。后台解析时一并生成稀疏留白计划，留白与背景沿既有约 8ms 时间片施加；更换正文清空 annotations，主题更新复用样式。

- 冲突外部读取使用单个可取消请求及文件通知版本，重复通知合并；读取或确认期间的新通知使旧结果失效并触发一次补读。保存开始或窗口销毁使读取失效，晚到成功与异常均不回写。接纳时才判断未保存编辑；保留内容只更新已确认磁盘版本，不重写正文或清除撤销记录。Scintilla 仅插入/删除通知触发冲突解析，样式和标记通知不产生下一轮解析；复用已有计时器与监听，不增加依赖、线程或常驻进程。
- 文本 diff 在读取两侧内容前分别检查 10 MB 上限，生成过程中检查 20 MB 输出上限；任一超限立即停止正文生成并返回摘要。
- 工作区 Diff 只缓存一份当前文件补丁，单栏/双栏切换在后台解析并复用该补丁，不重新调用 Git。该补丁受 20 MB UTF-8 输出边界限制，转为托管 UTF-16 字符串最多约占 40 MB，此外仍有解析和正文控件开销；缓存不按标签数累积，文件或比较选项变化时替换，关闭工作区 Diff、切换工作区或销毁窗口时释放。界面请求的完成范围包含查询与最终显示模式的排版，版本检查同时阻止过期查询和排版覆盖新选择。
- `GitDiffNavigation` 以保留补丁段边界的行类型序列计算连续变更块首行，工作区 Diff 与历史/引用比较共同使用；分别映射到单栏和双栏的可见正文行号。算法单次线性遍历，仅保存变更块位置，元数据不计正文行，无换行标记不拆分替换。
- 工作区 Diff 的文件边界提示由一个不进入 Tab 顺序的原生子控件绘制，只保存方向与候选文件路径，不创建计时器、线程、正文副本或窗口级通知。跨文件定位意图随当前查询作用域传递，查询和排版版本有效时才应用；Scintilla 定位允许不改变焦点。临时禁用导航按钮清空 Win32 焦点时，仅在原窗口仍为前台、用户未进入其他控件且请求仍有效的条件下恢复该按钮焦点。隐藏、关闭、改选、滚动或 Esc 清除待跨文件状态。
- 历史/引用比较视图和回滚预览按查询版本与排版版本拒绝晚到结果；取消令牌贯穿比较视图、本地历史适配器和 Git 查询。加载延迟提示只由当前请求收尾，选项查询期间不对旧补丁重新排版。主窗口仅保留比较标签的引用和路径，正文补丁由比较视图持有；关闭标签清空补丁及四个原生正文，显示模式切换后释放隐藏模式正文，暂时切换到普通标签时保留当前比较。
- 文件历史右侧按需创建独立的 `NativeGitComparisonView`，复用已有原生比较工具栏、文件信息、正文、导航与排版，不创建第二份补丁缓存。面板只保留提交/路径查询键；改选、隐藏、收起详情、返回和销毁同时取消比较视图内部的选项查询与排版。根提交、合并提交及忽略空白统一由本机 `git show --root --diff-merges=first-parent` 生成普通双侧补丁，开启忽略空白时附加 `--ignore-all-space`；不将根提交的不存在父引用交给普通引用比较服务。
- 日志上下文快照另保存当前筛选是否已有成功接纳的页面，不能用条目数判断初始化是否完成。首次直接进入文件历史后返回时，未完成的日志按恢复筛选补查；真正的空结果与已有列表均直接复用。文件历史提交行在原列表内按作者、日期、标题绘制，切换布局不新建列表；横向内容宽度收回后同步清除无效偏移，不改变选择或额外读取 Git。
- 历史变化文件入口单独维护当前激活的提交哈希、文件路径、请求版本和取消源，同键进行中的激活复用一个任务。选择、提交或历史上下文变化时取消旧查询，回写前再次核对版本与当前选择；查询结束释放取消源及任务引用，不额外缓存正文。主窗口关闭比较标签同时通知历史入口取消待完成的文件/引用查询；引用查询除操作版本外还检查实际取消状态，取消和销毁后的收尾不得访问原生控件或恢复标签。
- 历史文件激活时主窗口先建立比较标签身份，将文件查询委托与取消令牌交给比较视图。视图沿用同一查询版本、延迟加载和排版链路，失败与取消保留文件身份并在正文收尾；异步完成不再次调用主窗口排版或激活。主窗口打开普通文件只隐藏比较视图，已加载的相同提交文件或摘要直接复用；真正关闭标签才清空正文和取消查询。历史标题栏复用既有取消控件，慢文件查询不禁用文件列表。
- 历史/引用比较的键盘导航由主窗口消息循环转交当前可见比较视图，Tab 顺序按可操作按钮、当前正文和标签栏显式排列。Enter 复用原生按钮点击，空格沿用原生按钮行为；差异定位调用不抢焦点的 Scintilla 接口。差异总数来自已有变更块集合，使用一个不进入 Tab 的原生静态控件，加载或非正文状态清空，不创建新查询、计时器或正文缓存。
- `Ctrl+P` 调用 ripgrep 时始终应用 `.gitignore`；全仓搜索的“包含忽略文件”不能取消对 `.git` 的永久排除。当前文件搜索和全仓搜索默认使用字面量模式，并把区分大小写、全字匹配和正则开关映射为明确参数。
- 全仓搜索在第 1001 条结果出现时终止 ripgrep，并显示统一的截断提示；默认总超时为 15 秒。
- 快速打开和全仓搜索的请求在输入线程捕获查询快照后异步执行；每个浮层只允许一个 ripgrep 请求串行运行，新的查询先取消并等待旧进程退出，再启动最新请求。加载提示延迟 150 毫秒，完成、失败和取消通过浮层私有窗口消息回写，不依赖调用方同步上下文。关闭、销毁或过期版本会清除未分发动作，不能更新控件、焦点或预览；输入法组词期间不启动查询，也不拦截 Enter、Esc 和 Tab。
- 内置终端的 ConPTY Shell 在终端 WebView2 初始化与首次导航期间并行创建，先以 80×24 初始尺寸启动；页面 ready 后补发实际列行尺寸。Shell 在页面 ready 前产生的输出由会话暂存并在订阅输出事件时补发，关闭或初始化失败时必须等待并释放该会话，不能遗留 Shell、浏览器进程或会话目录。
- Worktree 管理窗口的列表读取、可移除检查和创建／移除命令均在后台执行，结果通过窗口私有消息按操作身份回到 UI 线程；取消、模式切换、关闭或宿主销毁会清除待接纳结果，晚到结果不得访问控件。失败只更新右侧详情内的局部说明并保留新建草稿，成功后再按当前工作区事实刷新列表；布局只滚动右侧正文，不重建左侧列表、底栏或宿主窗口。Worktree 移除先校验 Git 干净状态，再查询目标 Augit 窗口管理的内置终端会话；外部终端不参与检测，任一已知条件不满足时不调用 `git worktree remove`。
- 每个内置终端会话使用独立 ConPTY、独立 WebView2 用户数据目录和带 `KILL_ON_JOB_CLOSE` 的 Windows Job Object；关闭时先结束 Job 中的 Shell 与子进程树，再关闭专用 WebView2 浏览器进程并删除该次会话目录。工作区会话锁位于 `%LOCALAPPDATA%\Augit\TerminalSessions`，进程异常退出后由文件句柄自动释放，Worktree 移除持有同一把排他锁以避免检查与移除之间启动新终端。
- 终端原生标题壳在打开请求内同步创建并归主窗口持有，先显示加载状态，再异步创建 WebView2 和 Shell；WebView2 宿主也在初始化前归终端面板持有，并保留加载期间最新的尺寸与可见性。完成时核对面板身份及工作区，不无条件切换底部窗口或焦点；重复打开共享启动任务，旧会话的退出/输入失败回调不得写回新会话。
- WebView2 的环境与控制器创建不能直接取消。关闭正在初始化的面板时先标记释放、取消页面就绪等待，创建回调仍由原 STA 消息循环接收，返回后释放晚到的控制器、专用进程和目录，不再启动 Shell。关闭主窗口时先隐藏窗口，等待所有在途终端启动收尾后才销毁 HWND 并退出消息循环；不另建线程、不预热浏览器，也不通过同步等待阻塞 UI。

## 6. 性能设计与验收口径

### 6.1 启动与常驻资源

- 启动路径不扫描整棵目录、不读取 Git 全历史、不创建 WebView2、不创建 shell，也不预热后续阶段能力。
- 文件树仅枚举用户当前展开的目录；大列表使用虚拟化；Git 历史分页读取。
- 项目树目录枚举和排序仍在线程池执行。目录结果按完整路径、名称和类型与当前直接子项比较，保留未变化项的原生节点及子树，只增删变化项；F5 与外部事件共用同一增量入口，不重新初始化整个树。临时路径字典仅属于一次目录应用，不保存历史快照。新增、删除每 32 项检查耗时，约 4ms 后交回消息循环，恢复前检查工作区代次、节点身份和事件版本；同一目录的加载标记覆盖枚举与界面应用全过程，避免重复插入。选中项删除时选择仍存在的后继或前驱，组为空时回到父目录；未发生新输入才恢复原首个可见节点，不恢复旧展开快照或覆盖用户主动收起。没有新增依赖、线程、常驻计时器或额外窗口；单次 Win32 调用和删除深子树仍需单独测量，不能由分批策略推导全部场景满足硬实时上限。
- 目录应用期间保留原有无业务身份的占位项，必要时临时补上同类占位，完成或旧请求失效后仅在原节点仍有效时移除，避免删除最后一个子项导致 Win32 提前收起目录。显式展开/收起消息完成后再次读取原生实际状态，不能仅使用加载开始时的缓存标记。目录快照按精确名称匹配并逐项消费，原生顺序仍采用目录服务的 Windows 自然排序；登记顺序不同、大小写名称并存或重复输入都不能误判为相同结构。
- 文件树恢复状态最多保存 50 个目录路径，首次界面可操作后才分批恢复，不为恢复状态执行递归扫描。
- 外部变化由事件驱动并合并处理，空闲时不轮询整个仓库。
- 普通文档标签关闭以实际前台视图判断是否需要切换：后台关闭只修正保留文档的索引、重绘标签条并销毁目标视图，不递增其他活动文档的选择请求版本，不重新激活普通文档或重排主窗口。异步读取完成后按文档身份重新取得索引，已删除的文档不得创建视图；比较前台关闭最后一个普通标签不得覆盖比较正文。
- 项目树悬停由既有树 subclass 和 Windows `TrackMouseEvent` 维护一个节点及客户区指针坐标；只有命中节点变化才使旧、新可见行失效，同一行内移动不重绘。滚动、目录结构和行高改变后复用原生命中查询，不扫描目录或请求 Git。隐藏、移出和销毁清除状态及鼠标移出跟踪，销毁解除 subclass；无新增窗口、线程、应用计时器或运行时依赖。
- 标签关闭叉使用现有标签栏的鼠标捕获处理按下与松开，不进入原生按钮的焦点激活路径；只保留本次目标文档身份，松开时核对仍命中同一关闭目标，取消捕获时清空。正常标签激活保留原生按钮处理，不新增控件、线程或依赖。
- 比较标签复用同一关闭捕获流程，以比较类型与路径识别按下目标。工作区比较只有一个标签槽位，Enter、双击或“显示 Diff”均复用该槽位；Changes 选择在 Diff 前台时原位更新，普通文档前台时后台更新，不创建按文件固定的额外标签。关闭时取消查询、结束选择跟随并清空 Scintilla 正文，保留 Changes 列表和输入状态。历史比较在已有比较上下文中随提交和文件选择复用同一标签，普通文档前台时不抢占；关闭后解除跟随。引用比较仍独立维护，不被工作区或历史选择覆盖。
- 普通文件读取完成后，以文档身份、路径、工作区和选择版本检查结果归属。新视图使用既有正文占位区的客户坐标单独设置边界，不调用主窗口全局布局；只有最后的有效选择且两类比较均不在前台时才能显示。定位行可不设置焦点，输入恢复同时核对读取前后的焦点、前台窗口、树选择和树首个可见项；较新的全局状态提示由状态版本保护，隐藏文档不能回写全局状态。
- 文档自身保存当前读取结果的状态文字，重新加载时先重置，再用 JSON 格式错误等实际结果更新；切回标签不复用旧错误。启动恢复只请求一次活动文档，后续目录展开只在原选择和输入上下文仍有效时同步树选中与首行，不再次激活文档。比较关闭返回未加载普通标签时复用其读取任务并显示读取占位。以上沿用已有任务和视图，无新增运行时依赖、线程、常驻进程或正文副本。
- 普通文本与 JSON 在状态仍为有效文本、分类和解析目标未改变时原位更新现有 Scintilla，不重建控件、重新应用字体或全局布局。相同读取结果跳过正文写入；已有 Blame 的刷新先清除旧归属和点击映射，避免把旧提交信息套在最新工作区内容上。有效图片复用窗口并重新解码、替换位图，保留缩放和有效偏移；图片结果未携带像素内容，不能用相同路径或大小跳过解码。文件失效、超限、分类或解析目标变化仍重建对应信息页。
- Blame 关闭与外部刷新共用归属清理入口；刷新不转移焦点，主动关闭则把焦点交回只读正文。关闭按钮与查找输入使用不同控件标识，加入既有 Tab 与 Enter 导航，不增加窗口、线程或计时器。Scintilla 通知结构中的位置字段使用原生指针宽度；边栏点击依据 `SCN_MARGINCLICK.position` 经 `SCI_LINEFROMPOSITION` 转为文档行，不读取只属于修改通知的 `line` 字段。
- Blame 三列在既有 Scintilla margin 内用 GDI 绘制，只遍历可见文档行；日期、作者、行号与完整提交映射共用逐行记录。绘制缓存仅为当前边栏大小的 32 位位图和一个字体，滚动时复用，尺寸或外观改变时重建，清除归属、控件销毁及宿主提前销毁均释放，不增加独立窗口或常驻线程。该绘制路径仍需用真实屏幕核对与正文的字体一致性。
- 历史面板的 Blame 查询独立维护取消源、请求版本与目标完整路径；选择变化、关闭目标、隐藏面板、刷新查询和销毁时取消。同一取消源覆盖 Git 查询和随后等待正文读取的两个阶段，整条请求结束后释放，结果按版本与取消状态接纳。Git 读取结束后主动打开目标文档，此次内部选择只推进文档版本、不取消自身；其后任何用户选择仍使请求失效。主窗口再以取消令牌、文档选择版本、工作区、前台视图类型和路径约束归属写入。进入比较标签同样推进文档选择版本，防止返回普通文档时重新接纳旧 Blame。
- Scintilla 更新分别保存锚点与光标，按新 UTF-8 字符边界限制位置，再恢复选择方向、纵向首行及横向偏移；完成或异常收尾保持只读。查找继续位置属于文档，更新仅将其限制在新显示文本范围并重新计数。OwnerDraw 文档按钮的换行、空白符、大小写、全字和正则状态由文档字段持有，绘制与命令共用，不能依赖原生 `BM_GETCHECK/BM_SETCHECK` 保存状态。
- Markdown、终端、大 diff 和冲突数据必须有明确生命周期和容量边界。
- 同一目录的后续实例只负责通知已有窗口并退出，不重复初始化完整界面。

### 6.2 正式测量口径

- 使用 Release、win-x64、非 self-contained 发布版，不连接调试器。
- 冷启动从创建进程开始，到主窗口完成首次渲染并能够响应界面输入为止；1 秒是优先优化目标，超出时记录原因和后续优化项，不以牺牲界面响应、稳定性或视觉还原为代价。
- 核心内存在界面可操作后空闲 5 秒测量，统计 Augit 核心进程树的 Working Set 总和；100 MB 是优先优化目标，超出时必须记录增量、定位可回收资源并继续优化。
- 核心测量关闭 Markdown 预览、终端和冲突解决器；这些按需能力单独记录打开前后的进程树和增量内存。
- 正式测试使用 10 万文件测试仓库，记录 Windows 版本、CPU、内存、磁盘、.NET Runtime、发布方式和测量结果。
- 测试机不得存在 E-SafeNet 等第三方进程注入。无法避免时只记录诊断数据，不宣称通过或失败。

### 6.3 按需资源回收

- Markdown 和终端分别连续打开、关闭 10 次。
- 每次关闭后，对应 WebView2、shell 和 WSL 子进程必须退出。
- 主进程允许保留可复用缓存，但内存不得随开关次数持续线性增长。
- 第 10 次关闭并空闲 10 秒后，主进程 Working Set 不得比首次关闭后高出 20 MB。

### 6.4 性能不达标处理

- 1 秒冷启动和 100 MB Working Set 是持续优化目标，不作为牺牲交互流畅性、稳定性或规格视觉还原的硬门槛；任何超出都必须保留可复现测量、原因分析和下一步优化记录。
- 发布版不达标时，先在同一台机器使用同一发布方式测量最小空白 C#/.NET 10 原生 Win32 程序，再分解 Augit 的增量成本。
- 若干净环境中的最小原生 Win32 基础开销仍使目标不可达，记录证据和增量成本，继续以交互流畅性为优先优化方向。
- 改用 C++、托管桌面框架或其他技术栈属于新的架构决定，必须获得用户明确授权。

## 7. 本地数据与分发

- 设置、最近目录、窗口、标签和文件树展开状态只写入 `%LOCALAPPDATA%\Augit`，不向工作区写 Augit 配置。
- 内置终端首次默认启动 Windows PowerShell，用户主动选择后才使用其他 shell 或自定义命令；配置失效时返回明确错误，不静默回退。xterm.js 的 scrollback 固定为 2000 行。
- 终端网页在宿主尚未布局时保留默认 80×24 行列；原生宿主设置非零正文尺寸后才发送布局就绪消息，允许 fit 插件同步真实行列。零尺寸不把已有会话缩成临时微小视口，连续布局仍合并到一个动画帧；输出与输入不依赖该布局握手。首屏与命令输出回归使用与正式应用相同的独立 WinExe 宿主，通过公开 WebView2 接口断言实际正文与独立命令输出行，控制台测试宿主不能代替此验收。
- 关闭空闲终端时直接结束 shell；存在前台命令时先确认，再终止 shell、前台命令及其整个子进程树。
- 发布版依赖 .NET 10 Runtime 和 WebView2 Runtime，不依赖 .NET Desktop Runtime。正式产物的 .NET 兼容下限以 `Augit.runtimeconfig.json` 为准，检测到兼容的已安装补丁版本时不强制更新；缺失运行时时，安装版先向用户说明，经确认后从微软官方下载并安装锁定版本。下载地址、版本和完整性校验必须固定并验证，不提供完整运行时离线安装包。
- 运行时具体版本、微软官方下载地址和完整性信息统一维护在[运行时依赖锁定基线](runtime-dependencies.md)中。
- 提供安装版和便携压缩包，不提供 self-contained 首版包。便携包不安装运行时，缺少依赖时只说明缺失项和官方下载入口。
- 随程序分发的可执行文件、前端库和 NuGet 依赖必须附带相应许可证。
