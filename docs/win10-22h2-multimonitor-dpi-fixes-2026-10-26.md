# Windows 10 22H2 多显示器 DPI 修复与扩展验证（2026-10-26）

## 结论

在 Windows 10 Pro 22H2 `10.0.19045.6456` 的双显示器实机上，修复并复验了三个 DPI 相关缺陷：

- **M1**：真实鼠标跨屏拖动后逻辑窗口尺寸不再缩小；100% ↔ 125% 双向都保持 CSS `1180×760`。
- **M3**：混合 DPI 启动按目标显示器自己的 DPI 解释保存位置；125%/175% 主屏 + 100% 副屏时副屏窗口不再被放大或回退到主屏默认位置。
- **M2**：Settings 子窗改用 Owner 当前显示器 DPI；175% 下 CSS 从 `891×576` 恢复为 `1040×672`。

扩展验证覆盖 150%、175%、反向“主屏 100% + 副屏 125%”、负坐标布局、模拟热插拔、深色 1024×640 窄窗、rc.2 源码包构建/便携运行/安装器。除三屏（无第三块可用显示器）外均通过；live-shell 通过 2379 项断言。

Shell 测试 `267/267` 通过；行为修复提交 `7892c34`（`fix(shell): keep logical window size across monitor DPI changes`），启动显示器选择补强与 3 个单元测试提交 `c0f80e9`（`test(shell): cover per-monitor startup DPI selection`）。

## 初始缺陷与复现

### M1：真实拖动跨 DPI 不保持逻辑尺寸

修复前，主窗 `1180×760` 逻辑（100%）拖到 125% 副屏后变成物理 `1280×800`、CSS `1024×640`；拖回 100% 后仍是 `1280×800`、CSS `1280×800`。根因是 `WM_DPICHANGED` 只更新 `_effectiveDpi`，把尺寸交给默认过程；默认建议矩形和最小跟踪尺寸都不能保证逻辑视口。

### M3：混合 DPI 启动按系统 DPI 解释保存位置

主屏 125%、副屏 100% 时，保存于副屏的逻辑 `(2660,120)` 被按系统 120 DPI 放大成物理 `(3325,150)`，窗口变成 `1475×950`、CSS `1475×950`，右侧越界。主屏 175% 时同一保存位置甚至会被放大到虚拟屏外并回退到主屏 `(80,80)`。

### M2：Settings 跟随系统 DPI 而不是 Owner 显示器

进程在主屏 150% 时启动，随后主屏切到 175%，再打开 Settings：Owner 已是 168 DPI，Settings 仍按旧的系统 144 DPI 计算，物理 `1560×1008`、CSS `891×576`，内容被压缩。

## 修复

提交：`7892c34`。

1. **`OnDpiChanged` 按逻辑尺寸缩放并延迟到移动循环结束**
   - 非拖动路径：用旧/新 DPI 把当前物理尺寸换算回逻辑尺寸，再缩放到新 DPI；结果收敛到当前显示器工作区。
   - 真实拖动路径：`WM_ENTERSIZEMOVE` 记录起始 DPI 和客户区；`WM_DPICHANGED` 只记录待应用尺寸；`WM_EXITSIZEMOVE` 再 `SetWindowPos` 并按工作区收敛。避免在系统移动循环内抢位置导致窗口被推到屏幕外。
2. **启动时按目标显示器 DPI 解析保存位置**
   - `EnumDisplayMonitors` 枚举每块显示器，用各自的 `GetDpiForMonitor` 解释保存的逻辑坐标；选中候选点落在该显示器内的那块，再用它的 DPI 计算尺寸和工作区。
   - 解决 M3，也覆盖保存位置被系统 DPI 放大到虚拟屏外的情形。
3. **Settings 子窗使用 Owner 的 DPI**
   - 构造 Settings 时取 `GetDpiForWindow(owner)`，不再用 `GetDpiForSystem()`；解决 M2。

`ShellWindowSizing.ScaleForDpiChange` 及边界测试位于 `tests/Augit.Shell.Tests/ShellWindowSizingTests.cs`：1180×760@96→120 = 1475×950；1280×800@120→96 = 1024×640；1024×640@96→168 = 1792×1120；非法输入原样返回。

## DPI 组合复验

所有尺寸为物理像素；CSS 为网页层 `innerWidth×innerHeight`。

| 场景 | 结果 |
| --- | --- |
| 真实拖动 125%→100% | `1475×950@120` → `1180×760@96`，CSS `1180×760`，dpr 1.0 |
| 真实拖动 100%→125% | `1180×760@96` → `1475×950@120`，CSS `1180×760`，dpr 1.25 |
| 100%→150% | `1180×760@96` → `1770×1140@144` |
| 150%→100% | `1770×1140@144` → `1180×760@96` |
| 100%→175% | `1180×760@96` → `2065×1330@168`，工作区收敛到 `y=40`（工作区高 1370） |
| 175% 下 Settings | 物理 `1820×1176@168`，CSS `1040×672`，dpr 1.75 |
| 125% 下 Settings/模态 | Settings `1300×840@120`，CSS `1040×672`；模态 `500×204@120` |
| 150% 下 Settings | 物理 `1560×1008@144`，CSS `1040×672` |
| 主屏 100% + 副屏 125% | `1180×760@96` → `1475×950@120`；Settings `1300×840@120` CSS `1040×672`；模态 `500×204@120` |
| 副屏 125% → 主屏 100% | `1475×950@120` → `1180×760@96` |
| 混合 DPI 启动（主 125/175，副 100） | 保存 `(2660,120,1180,760)` → 实际 `(2660,120)–(3840,880)`，`1180×760@96`，CSS `1180×760` |

125% 真实拖动双向、150/175 及反向副屏 125% 均保持逻辑 `1180×760`；175% 下窗口高度受 1440p 工作区限制，位置被收敛但尺寸本身正确。

## 负坐标布局

用 `SetDisplayConfig` 把 DISPLAY2 移到主屏左侧，副屏边界变为 `[-1920,0]–[0,1080]`，工作区 `[-1920,0]–[0,1040]`。

- 启动保存位置 `(-1800,120)`：实际 `(-1800,120)–(-620,880)`，`1180×760@96`，CSS `1180×760`。
- 最大化：`(-1928,-8)–(8,1048)`，客户区 `1920×1040`；恢复回 `(-1800,120)`。
- Settings：`(-1730,164)–(-690,836)`，`1040×672`；模态：`(-1410,418)–(-1010,582)`，`400×164`。
- 保存尺寸大于副屏工作区（`2500×1300`）：收敛为 `(-1920,0)–(0,1040)`，客户区 `1920×1040`。
