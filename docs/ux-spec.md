# Augit UX/UI 规格

## 1. 文档职责

本文规定 Augit 已确认产品能力在桌面界面中的布局、状态、交互、跳转和反馈方式。产品范围仍以[产品规格](product-spec.md)为准，技术实现仍以[架构说明](architecture.md)为准；当前界面设计不参考历史实施进度记录。

本文不得新增产品能力。若本文与产品规格冲突，以产品规格为准并停止对应实现，向用户确认后再修改文档。

配套 HTML 视觉稿入口为[视觉稿目录](ux-mockups/index.html)。视觉稿用于固定结构、比例、密度和状态，不代表可以引入浏览器运行时或前端框架；正式主界面继续使用 C#、.NET 10 和原生 Win32。

视觉稿自身必须能在离线状态下完整加载已登记的本地图形。未知图标显式报错，未校准图标与参考中的正常空列分别登记；离线验证通过不能代替原生窗口、同环境 PyCharm 对照或整体视觉验收。

## 2. 参考基线与探索结论

### 2.1 参考范围

- 实际探索版本：PyCharm 2026.2.1 New UI。
- 逐操作、证据等级和归档截图索引见 [PyCharm 黑盒探索记录](pycharm-blackbox-reference.md)。
- 实际探索工作区：当前 Augit 仓库。
- 探索内容：主框架、Project、Commit、工作区 diff、Git Log、提交详情、分支弹层、快速打开、全局搜索、当前文件搜索、终端、设置、克隆、Push 和 Git 主菜单。
- 探索方式：只读导航、选择、打开弹层和截图；没有执行提交、回滚、切分支、Push、Reset 或其他 Git 写操作。
- Git 命令语义和操作状态参考 IntelliJ IDEA 2026.2；窗口布局、信息密度、交互组织和可见图标以 PyCharm 2026.2.1 New UI 的黑盒探索为准。
- 参考目标：让 Augit 在自身能力范围内尽可能 100% 复原 PyCharm 的空间组织、信息密度、操作反馈、状态转换和已有功能图标。100% 是理想目标，允许像素级复制，也允许达到同等效果的其他实现方式；像素对照用于发现差异，不要求不同渲染环境下所有像素绝对相等。图标逐项匹配对应场景的轮廓、比例、线宽、填充、位置、颜色和状态；只能使用项目内自绘等效实现，不分发 JetBrains 官方资源文件、字体文件、商标或产品标志，也不引入 Augit 产品规格之外的 IDE 能力。Augit 自有品牌标记保留为唯一品牌例外。

### 2.2 核心探索结论

1. New UI 由全局标题栏、左右工具栏、工具窗口、编辑区、底部工具窗口和状态栏组成。每个区域有独立生命周期，局部状态变化不得重建全局结构。
2. 工具窗口是长期存在的工作上下文。Project 与 Commit 在左侧原位切换，Terminal 与 Git Log 在底部原位互斥；打开底部工具窗口不隐藏左侧工具窗口和编辑区。
3. 快速打开、分支选择和操作菜单使用非模态弹层，覆盖在当前工作上下文之上。关闭弹层后，原来的选中、滚动、焦点和分隔位置保持不变。
4. 设置、克隆、Push、Reset、Stash、Worktree、远端管理和危险确认使用模态窗口。背景保留且降低视觉权重，不重建主窗口。
5. PyCharm 在 Changes 中首次单击或键盘选择文件时先只改变选中行，不打开 Diff；按 `Enter` 或双击后才打开并激活 `Commit: 文件名` Diff 标签。已有 Diff 标签时，新的选择后台更新该标签，Diff 已激活则在原位更新；Commit 列表、底部 Git、分隔位置和其他标签保持不动。
6. 选择 Git 提交后，提交行立即高亮，右侧详情区异步填充。加载期间列表不消失、不跳回首行，也不重新创建引用树。
7. 相同选择的重复点击不会重新进入加载状态。外部刷新只有在数据快照实际改变时才更新对应区域。
8. 所有工具栏图标尺寸、间距和命中区域保持统一。图标按钮必须有悬停说明；禁用按钮保持位置，不通过删除按钮导致布局跳动，除非产品规格明确要求“不显示无效动作”的操作会话按钮。
9. 主要动作使用蓝色实心按钮，普通动作使用描边按钮，危险确认使用红色按钮。成功、错误和警告主要通过文字、图标及局部背景共同表达，不能只依赖颜色。
10. 页面不使用大卡片、仪表盘、超大标题或移动端式留白。桌面信息密度优先，标准正文约 13 像素，工具行高约 28 至 36 像素。

### 2.3 黑盒探索边界与证据等级

本规格只来自正常用户可执行的界面操作、可见文字、窗口截图和操作前后状态对比。探索过程不读取 PyCharm 安装目录、配置数据库、字节码、内部类、私有协议、进程内存或其他实现细节。

所有结论分为三个等级：

- **实测**：已在 PyCharm 2026.2.1 中通过正常点击、快捷键、选择、打开和取消观察到。
- **同构推导**：当前仓库无法安全触发，但根据已实测的同类 PyCharm 弹层、对话框和工具窗口模式设计；不得对外宣称为 PyCharm 实测细节。
- **产品裁剪**：PyCharm 存在对应入口，但产品规格明确排除，Augit 删除入口并重新分配剩余空间。

| 探索对象 | 证据等级 | 观察结论 |
| --- | --- | --- |
| Project、Commit 与编辑区并存 | 实测 | 左侧工具窗口原位切换，编辑标签、正文和底部区域不重建。 |
| Changes 首次单击或键盘选择文件 | 实测 | 只改变文件行选中，不打开 Diff、不抢占编辑区；文件复选状态不变化。 |
| Changes 按 `Enter` | 实测 | 打开并激活 `提交: 文件名` 临时 Diff 标签；下次打开其他文件时复用该临时标签。 |
| Changes 双击文件 | 实测 | 打开并激活唯一的 `提交: 文件名` Diff；后续选择继续更新同一比较，不固定原文件。 |
| Changes 已有后台 Diff 标签时改变选择 | 实测 | 后台更新该标签，不抢占当前普通文件；Diff 已激活时原位更新。 |
| Git Log 选择提交 | 实测 | 行立即高亮，右侧文件和提交详情在约 50 毫秒内局部稳定。 |
| Git Log 右键菜单 | 实测 | 菜单贴近提交行打开；Augit 仅保留产品规格支持的提交操作。 |
| 文件历史 | 实测 | 底部 Git 区增加路径专用标签，左侧历史列表和右侧版本内容并列。 |
| Blame | 实测 | 在现有文件正文左侧插入归属列，不创建独立全屏页面。 |
| 分支与引用动作 | 实测 | 标题栏弹层保持背景上下文，引用动作使用右侧二级菜单。 |
| 快速打开 | 实测 | 空态高度紧凑，结果随输入向下增长，输入框立即获得焦点。 |
| 主菜单 | 实测 | 汉堡按钮将标题栏左部原位切换为横向菜单，而不是普通悬浮卡片。 |
| 设置 | 实测 | 大型模态窗口保留并降低背景权重，左侧分类、右侧内容、底部动作固定。 |
| Clone | 实测 | 大型模态窗口，表单从上到下依次为版本控制、URL、目录和浅克隆。 |
| Push | 实测 | 左右分栏、底部固定动作；没有远端时显示 Define remote 且 Push 禁用。 |
| Stash 创建 | 实测 | 使用紧凑模态框，包含仓库、当前分支、消息、保留索引和固定动作。 |
| Terminal | 实测 | 在底部原位替换 Git Log，不改变项目树、编辑标签和编辑滚动。 |
| Reset、Smart Checkout 与危险确认 | 同构推导 | 使用已经实测的紧凑模态骨架，并按产品规格显示具体影响。 |
| 冲突列表与三栏解决器 | 同构推导 | 参考已实测工具窗口与模态层级，但内容和动作必须由真实 Git 状态决定。 |
| 平台 API、Force Push、多个 Changelist、子模块 | 产品裁剪 | 不显示禁用占位，不保留删除后产生的空白分组。 |

### 2.4 DPI 与测量口径

探索时 PyCharm 窗口截图为 2904 × 1740 物理像素，Windows 缩放约为 175%，对应窗口客户区约 1660 × 994 逻辑像素。本文和视觉稿使用逻辑像素，不把物理截图尺寸直接写入布局。

- 标题栏实测约 44 逻辑像素。
- 全局工具栏实测约 42 逻辑像素。
- 当前左侧工具窗口实测约 360 逻辑像素；视觉稿允许随窗口缩放到 300 至 360 像素。
- 当前底部工具窗口实测约 305 逻辑像素；视觉稿默认按客户区高度的 31% 计算，并限制在 180 至 305 逻辑像素之间，允许用户调整。界面字号增大时，最小高度按 `max(180, 4h + 80)`（`h` 为当前界面实际行高）扩展，确保标题、筛选／工具栏、提交行及至少一行详情正文完整可见。
- 树、列表和提交行实测约 27 逻辑像素。
- 可见工具图标约 16 逻辑像素，常用命中区约 28 至 32 逻辑像素。

## 4. 全局视觉系统

### 4.1 窗口骨架

主窗口从上到下固定为：

1. 标题栏：产品标记、主菜单、工作区名称、当前分支、快速搜索、设置和 Windows 窗口按钮。
2. 主区域：左侧工具栏、左侧工具窗口、编辑工作区。
3. 编辑工作区：编辑标签与正文；需要时在下方增加 Git 历史或终端工具窗口。
4. 状态栏：工作区路径、当前文件路径、编码、换行格式和只读状态。

标题栏、工具栏和状态栏不能因文件加载、Git 刷新或操作失败消失。

状态栏按当前活动视图显示文件身份，不能使用后台普通标签代替前台比较路径：

- 没有文档时显示工作区路径；文件加载期间显示本次打开的路径。路径过长时省略，悬停提供完整路径。
- 只有成功读取的普通 UTF-8 文本显示编码和磁盘原文的换行格式，分别支持 `LF`、`CRLF`、`CR`、`混合换行` 和 `无换行`。JSON 格式化显示和 Markdown 预览不改变这些磁盘事实。
- 图片、不可预览文件、未完成读取的文件及工作区/历史/引用比较只显示适用的只读标识，不继承后台文件的编码或换行；没有文档时也不显示只读标识。比较补丁不能用来推断原文件格式。
- 操作或错误提示与路径分别分配空间，长路径不能吞掉提示；普通文件类型不在路径旁重复显示。完整提示与格式也可通过状态栏悬停读取。
- 活动文件外部刷新后更新元数据；后台读取晚到或后台比较改选不覆盖前台文件状态。相同状态不重复刷新，不改变焦点、滚动和主窗口布局。

以上元数据适用范围与异步约束属于 Augit 的只读产品适配，不登记为 PyCharm 的新增实测结论。

### 4.2 尺寸与密度

- 标题栏高度：44 像素。
- 左侧全局工具栏宽度：42 像素。
- 全局工具按钮可见图标：16 像素；命中区域：32 × 32 像素。
- 左侧工具窗口默认宽度：当前参考窗口使用 360 像素；根据窗口宽度在 300 至 360 像素之间收缩；用户拖动后持久化。
- 底部工具窗口默认高度：默认字号按客户区高度的 31% 计算，并限制在 180 至 305 逻辑像素之间；参考窗口约 305 像素；用户拖动后持久化。若界面字号导致 `4h + 80` 超过 180，则以该值作为最小高度；超过 305 时参考上限同时扩展到该最小高度，不能产生无效尺寸区间。
- 工具窗口标题行：38 至 42 像素。
- 树、列表和提交行：27 至 30 像素。
- 普通控件高度：30 至 31 像素。
- 面板圆角：只用于主工具窗口外边缘、弹层和对话框，内容行不使用卡片圆角。
- 分隔线：1 像素中性颜色，不使用厚重描边。

窗口小于推荐宽度时优先压缩左侧工具窗口和 Git 详情区，不缩小字体，不把桌面布局改成移动端纵向页面。

左右和上下工具窗口分隔条从按下时的实际显示尺寸计算指针增量，保留按下处偏移，不因 4px 间隙或表面内缩产生初始跳动。拖动、显示与保存使用相同的尺寸边界；已保存尺寸超出当前视口时，反向拖动从当前可见边界立即生效。同一实际尺寸不重复布局，保持焦点、文件、提交和滚动上下文。松开接纳最终指针位置；Esc、系统取消、捕获转移、隐藏、禁用、折叠对应工具窗口或 DPI 改变结束拖动，保留已显示尺寸。拖动中的 Esc 不同时关闭查找条。

### 4.3 字体

- 界面字体默认使用 `Microsoft YaHei UI`，保证中文与拉丁文字共享明确的无衬线字体；用户可独立选择界面字体和界面字号，字体缺失时按设计系统明确回退。
- 界面正文默认 13 像素，工具窗口标题使用界面字号的半粗体。
- 只读文本、diff、冲突和终端使用独立的等宽字体和等宽字号，默认等宽字号为 13 像素；修改等宽设置不得改变界面文字。
- PyCharm 同样允许分别调整界面字体、界面字号、等宽字体和等宽字号；Augit 保留这四个独立设置值，并以界面 13px、等宽 13px 作为默认基线。进行截图或像素对照时，必须先把参考窗口与 Augit 的实际字体、字号和 Windows DPI 设为相同，不能把参考窗口已有的个人设置写成产品默认值。
- 只允许普通和半粗两个主要字重，避免过多粗体层级。
- 次要路径、时间、作者和状态使用同字号的弱化颜色，不缩小到难以阅读。
- 调整界面字体或字号时，主框架标题栏、文件标签、项目头、树行、文件路径工具栏和状态栏按设计系统第 4.2 节实际字高扩展；图标尺寸保持。原文档控件、树选择和首个可见节点、正文选择方向与滚动位置保持，不重新打开文件或查询 Git。标题栏主菜单和状态栏右侧文字按字宽分配，路径在剩余区域省略；等宽正文不跟随界面字号改变。

### 4.4 颜色

- 浅色主背景为冷灰色标题栏与白色内容面板。
- 深色主背景为深灰标题栏与接近黑色的内容面板，不使用纯黑大面积背景。
- 当前全局工具入口使用蓝色实心底和白色图标。
- 当前列表行在列表获得焦点时使用浅蓝背景；焦点移出列表（包括同一工具窗口的输入框或按钮）后保留选中项并切换为 PyCharm 的中性灰背景。选择不会因此取消，也不会触发文件打开、Diff 请求或 Git 勾选变化；鼠标悬停使用更弱的中性或浅蓝背景。
- 提交文件复选框的全选使用蓝底白勾、部分选中使用蓝底白横线；折叠分组不改变复选状态。分组标题只在被选中时显示行选中背景，文件勾选和行选择互不混用。
- 新增、删除和修改分别使用绿色、红色和蓝色语义，同时显示状态文字或文件状态标记。
- Diff 新增块使用浅绿，删除块使用浅红，修改块使用浅黄或局部词级高亮。
- 焦点使用蓝色边框或蓝色外环，必须在浅色和深色主题下清晰可见。

### 4.5 图标

- 使用自绘等效图标逐项复原 PyCharm 的可见几何、比例、线宽、填充、位置、颜色和状态；视觉结果应与参考图标一致，不分发 JetBrains 官方图标文件。
- 图标语义、位置、排序和状态必须与参考界面一致；参考场景有图标而实现缺失属于缺陷，不得因此隐藏已有动作，补齐前可使用明确文字入口保持动作可达。参考场景本来没有图标时保持空列，不从工具栏或其他菜单移入同名图标。
- 通用工具图标使用 16 像素网格；可见笔画、线宽、端点和填充以对应参考图形为准，标签关闭、下拉箭头等辅助图形遵循设计系统登记的组件尺寸。
- 每个图标按钮必须提供悬停说明；仅图标无法明确表达危险影响时必须使用文字按钮。
- 禁止用 Emoji 代替正式界面图标。

## 5. 全局交互模型

### 5.1 工具窗口切换

左侧顶部固定顺序为项目、提交、搜索；左侧底部固定顺序为终端、Git 历史。

- 点击已经激活的左侧入口：折叠对应工具窗口，再次点击恢复上次宽度或高度。
- 点击同区域的另一个入口：原位替换，例如项目切换为提交，Git 历史切换为终端。
- 切换工具窗口不关闭编辑标签，不改变当前文件，不重置编辑滚动位置。
- 左侧和底部工具窗口可以同时打开。
- 终端和 Git 历史互斥，不允许同时占用底部区域。

标题栏汉堡按钮的菜单行为固定如下：

- 点击汉堡按钮时，标题栏左侧原位显示“文件、视图、Git、终端、设置”五个文字入口，不弹出一张替代标题栏的悬浮卡片。
- “文件、视图、Git”入口打开贴近入口的动作菜单；菜单关闭后恢复原有标题栏入口、当前分支和当前文件上下文。
- “终端”直接切换底部终端工具窗口；“设置”直接打开设置模态窗口；两者执行前先恢复普通标题栏。
- 按 `Esc` 关闭内嵌菜单并恢复原有标题栏；窗口按钮、项目树、编辑标签和工具窗口状态保持不变。

标题栏的默认、悬停、按下、禁用和焦点状态按设计系统第 6.4 节绘制。工作区入口常驻淡蓝底色，不能只在悬停时出现；键盘访问按钮时焦点环清晰可见。已获得焦点且可见、启用的标题栏按钮按 `Enter` 执行原点击动作，长按不重复切换；空格保留原生按钮行为。鼠标移入、移出或焦点变化只重绘相关按钮，不打开文件、不查询 Git、不重排主框架；隐藏、禁用或销毁清除过期悬停。

### 5.2 标签

- 双击文件或按 `Enter` 打开正式标签。
- Changes、Git 历史或搜索结果的单击只改变选中项；已有临时预览标签时可在后台更新该标签，但不因普通列表选择抢占编辑区。
- Changes、Git 历史或搜索结果按 `Enter` 打开并激活临时预览标签；下一个打开结果复用该标签。
- Changes 只保留一个工作区比较标签。双击、`Enter` 或“显示 Diff”均打开并激活该标签；后续文件选择持续更新同一标签，普通文档处于前台时只后台更新，不抢占焦点。关闭比较后解除跟随，下一次明确打开动作才重新创建比较。
- `Ctrl+W` 关闭当前标签，激活同一标签组中的相邻标签。
- 中键或关闭叉关闭后台普通文件标签只移除目标标签并释放其视图，不重新激活当前文件，不改变正文、查找输入、项目树选择、焦点和滚动位置。关闭叉按下时不抢焦点，移出原关闭目标再松开时不关闭其他标签。比较处于前台时，即使关闭最后一个普通文件标签，也不切走比较或显示空白页；其他活动文档或比较的进行中请求保持有效。对应参考与适配边界见 `PY-TAB-CLOSE-01`。
- 工作区 Diff、历史和引用比较的关闭叉遵循相同的按下、松开及取消捕获规则。关闭后台比较只移除目标标签、取消其请求并释放其正文，不重排主窗口、不抢走前台焦点。关闭工作区当前比较会话后，Changes 的单击和无变化刷新不得重新创建该标签；再次按 Enter、双击或执行“显示 Diff”才能打开。工作区 Diff 始终只有一个跟随 Changes 选择的比较标签，关闭后解除跟随；关闭比较保留 Changes 的选中行、勾选、草稿和滚动。历史比较仅在已有比较上下文中随提交和文件选择更新，普通文档前台时不抢占，关闭后解除跟随。
- 外部文件变化后保持标签顺序、当前标签、选择范围和滚动位置，除非文件已不存在。

### 5.3 弹层与对话框

- 快速打开、分支选择和右键菜单是非模态弹层；当前文件搜索使用正文顶部占一行的查找条。
- `Esc` 只关闭最上层弹层或取消当前搜索，不关闭其下方工具窗口。
- 设置、克隆、Push、Reset、Stash、Worktree、远端管理和危险操作确认是模态对话框。
- 模态对话框打开时背景结构保持可见，不重新创建主界面。
- 对话框取消后恢复打开前焦点；确认后焦点回到触发区域或直接进入结果区域。
- 跳转行、检出引用、创建跟踪分支和重命名共用紧凑单行输入窗口。打开后输入框获得焦点；`Tab` 按输入框、取消、确定、标题栏关闭循环，`Shift+Tab` 反向循环。输入框或确定按钮上的 `Enter` 确认；取消或关闭按钮上的 `Enter`、`Esc` 和标题栏关闭均取消。中文输入法仍在组词时，`Enter`、`Esc` 交给输入法，不提交或关闭窗口。
- 紧凑输入窗口与遮罩都归属顶层主窗口，打开期间主窗口禁用，关闭后恢复先前启用状态和焦点；不重建背景页面。输入内容的业务校验仍由原入口完成，窗口本身不执行 Git 或文件写入。

### 5.4 焦点与键盘

文件查看工具栏、图片动作和查找开关的悬停与焦点反馈只更新目标按钮，不改变正文选区、阅读位置、查找查询、选项或显示模式；切换普通文件标签、隐藏查找条、禁用动作及销毁时清除过期悬停。各类按钮保持原有键盘顺序与命令，选中开关和选中模式的底色优先于悬停，不以悬停代替激活。

- 工具栏按钮、树、列表、标签、输入框和正文均可使用键盘访问。
- `Tab` 在当前区域内按视觉顺序移动焦点，不先穿越所有全局工具入口。
- 树使用方向键移动，右键或菜单键打开上下文菜单，`Enter` 执行默认动作。
- 列表选择变化先只更新选中状态；只有已有预览标签，或用户按 `Enter`/双击/执行“显示 Diff”时，才请求或更新预览。同一项重复选择不重复加载。
- 固定快捷键严格遵循产品规格，不把 PyCharm 的快捷键原样带入 Augit。

## 6. 异步加载与刷新不变量

本节是界面稳定性的强制约束。

### 6.1 局部更新原则

- 异步操作只能更新负责该数据的最小内容区。
- 不允许因 diff、历史、文件、Markdown 或 Git 状态加载而隐藏整个编辑工作区。
- 不允许通过先清空主区域、后重新创建控件来表现加载。
- 主框架、工具窗口、分隔位置、标签条和非目标区域在加载期间保持像素位置不变。

### 6.2 快照判定

每次本地文件或 Git 事件合并后生成稳定快照。快照至少包含：

- 当前工作区路径与仓库可用状态。
- 当前分支和 HEAD。
- Changes 与 Unversioned Files 的路径、状态和排序。
- 当前 Git 操作会话类型与可用动作。
- 当前已选文件或提交的稳定标识。

新快照与旧快照相等时：

- 不重建列表。
- 不重设选中项。
- 不重新计算或渲染 diff。
- 不改变工具窗口大小。
- 不触发布局。
- 可以更新“最后检查时间”等非布局状态，但首版没有必要显示该信息。

### 6.3 Diff 请求

Diff 请求键由仓库、文件路径、比较基准、单栏或双栏、忽略空白和重命名选项组成。

- 请求键与当前已经显示的 diff 相同时直接复用结果。
- 单栏与双栏属于显示模式：相同文件、比较基准、内容版本和 Git 选项下复用已有补丁，只重新排版，不再次查询 Git；重复点击当前模式不触发加载。查询或排版期间切换模式时，按用户最后选择的模式完成，最终正文或摘要呈现前不得结束加载。
- 新请求开始后保留旧 diff，或在同一编辑内容区显示轻量加载占位；不能清空其他区域。
- 每个请求带递增版本号。旧请求晚于新请求返回时必须丢弃旧结果。
- 用户快速连续选择多个文件时只显示最后一次选择，前面请求可以取消或在完成后丢弃。
- 改选后的新 Diff 仍在查询或排版时，无变化的 Git 状态通知必须复用该进行中请求；不能拿屏幕上暂留的上一文件正文判断新请求是否失效。Git 文件列表的刷新独立完成，不能等待慢 Diff，后续新增文件和状态变化仍须及时进入列表。
- 发生真实外部变化时，仅当前文件受影响且请求键内容版本变化，才重新计算当前 diff。
- 失败时在当前 diff 区显示原因，并保留文件列表和当前选择。
- 从普通文件返回已加载的 Diff 时恢复正文或摘要。关闭工作区 Diff 后释放其补丁和正文，取消尚未完成的请求；旧任务返回不得恢复已关闭标签。

### 6.4 列表更新

- 路径和状态均未变化时保留原列表项对象。
- 部分变化时执行增量更新，保持未变化项、展开状态和滚动位置。
- 当前选中项仍存在时保持选中；不存在时选择同组最近邻项；组为空时显示稳定空状态。
- 刷新期间不得自动勾选或取消用户的提交复选状态。

### 6.5 加载反馈

- 预计低于 150 毫秒的操作不显示加载动画，避免闪烁。
- 超过 150 毫秒后在目标内容区显示小型进度指示或“正在加载…”。
- Diff 有旧正文时保留正文，并在该 Diff 的文件标题行提示加载；加载、完成与外部触发的重新计算均不覆盖其他操作的全局状态栏提示。
- 正文渲染完成前仍属于当前加载请求。二进制、超限、无文本差异和错误的最终说明必须持续可见，不能被加载指示的收尾隐藏；切回文本差异后再隐藏说明。
- 加载指示不得循环触发布局，也不得使用大面积白屏。
- 可取消操作在原操作区域显示“取消”，取消后读取并显示最新磁盘事实。

### 6.6 状态所有权与允许更新区域

| 状态 | 所有者 | 允许更新区域 | 明确禁止变化 |
| --- | --- | --- | --- |
| 当前工作区 | 主窗口 | 标题栏工作区名称、项目根节点、状态栏路径 | 已恢复窗口尺寸不得被默认值覆盖 |
| 当前左侧工具窗口 | 左侧工具区 | Project、Commit、Search 内容和对应激活图标 | 编辑标签、编辑滚动、底部工具窗口 |
| 当前底部工具窗口 | 底部工具区 | Git Log、文件历史或 Terminal 内容和激活图标 | 左侧工具窗口、编辑标签、编辑滚动 |
| 当前 Changes 文件 | Commit 工具窗口 | 文件行选中；已有 Diff 标签时只更新该标签正文 | 首次单击不得创建或激活 Diff；复选框、提交信息、列表滚动和其他标签 |
| 当前 Git 提交 | Git Log | 提交行选中、右侧变化文件和提交详情；已有历史比较时同步其文件与提交身份 | 引用树、筛选、提交列表滚动；普通文档前台时不抢占编辑区 |
| 当前快速打开结果 | 快速打开弹层 | 弹层结果行和临时文件预览 | 原工具窗口、正式标签和分隔位置 |
| 当前设置预览 | 设置对话框 | 当前设置控件和被预览的主题属性 | 未点击确定前不得持久化 |
| 当前 Git 写操作 | 操作触发区域 | 按钮进行态、取消入口、局部结果或冲突入口 | 不相关工具窗口和用户输入 |

任何实现如果无法明确指出状态所有者和最小更新区域，必须先补充本表或对应页面规格，不能直接通过重建主界面完成更新。

### 6.7 普通文件读取与恢复

- 文件读取结果属于原文件标签。完成时只创建、放置该标签的内容控件，不重新布局主窗口；是否显示必须重新核对标签仍存在、当前活动标签及比较视图状态。
- 读取期间切到工作区 Diff、历史或引用比较，旧文件就绪后保持隐藏；切回该普通标签时复用已读内容。普通文件之间乱序完成时，只显示最后选择的文件。
- 读取期间用户单击其他项目树行、滚动项目树或把焦点移到其他控件，已明确打开的文件可以完成显示，但不得重选树行、滚回原视口或抢回焦点。后台完成及构造期的文件错误不得覆盖较新的状态栏提示；文件再次激活时使用最新读取结果的状态。
- 关闭尚在读取的标签后，结果不得创建视图或恢复标签；关闭其前面的后台标签只改变索引，不使当前文件读取失效。
- 关闭比较后若返回的普通标签尚未就绪，正文显示该文件的读取占位，不能显示“从左侧文件树打开文件”的无文档提示。
- 启动恢复只激活原恢复文件一次；后续目录展开仅补齐树节点。恢复期间用户切换比较、打开其他文件、改变树选择或进入查找框后，恢复收尾不得重新激活正文、重选项目树或覆盖输入状态。

上述慢读取和乱序完成场景是 Augit 的稳定性契约。受控延迟自动化用于验证实现，不能记为 PyCharm 异步内部机制或异常路径的直接实测证据。

## 7. 页面规格

### 7.1 项目与文件查看

视觉稿：[打开工作区](ux-mockups/workspace-open.html)、[初始化仓库](ux-mockups/repository-init.html)、[项目和文件查看](ux-mockups/main-project.html)与[项目右键菜单](ux-mockups/project-context-menu.html)。

- 初始进入工作区时立即显示标题栏、全局工具栏、项目窗口、标签条和状态栏。
- 恢复标签时只创建当前活动标签的文件视图，其他标签先显示名称和状态。
- 项目树单击仅选择，双击或 `Enter` 打开正式标签。
- 项目树悬停由树控件独立维护，只重绘原悬停行与新悬停行，不改变选择、焦点、标签或触发 Git 查询；同一行内移动不重复重绘。移出或隐藏项目窗口时清除悬停，滚动及目录更新后按指针所在位置重新命中。选中态优先于悬停态，不能把失焦选中行的中性背景改成悬停色。
- 展开目录只读取该目录一级子项，显示局部加载状态，不锁住其他区域。
- 文件树刷新保持展开、选择和滚动位置。
- F5 和外部目录变化都增量更新当前已加载的目录；未变化项及其展开子树保持身份，只在新增或删除的行上做结构变动。大目录分批应用，期间仍可改选、滚动、收起目录或切换工作区；旧任务不能恢复先前的展开和选择，也不能向新工作区插入节点。尚未展开的目录不因 F5 递归读取。
- 文件树右键菜单只显示产品规格已经实现的动作。
- 打开底部 Git 历史时项目树和文件正文保持可见。

状态：无工作区、工作区加载、普通目录、Git 仓库、目录读取失败、外部变化、文件被删除。

### 7.2 普通文本查看

视觉稿：[普通文本查看](ux-mockups/text-viewer.html)。

跳转行输入状态见[紧凑输入窗口](ux-mockups/go-to-line.html)。此窗口根据现有模态规则适配，尚未取得 PyCharm 同场景直接对照；不将其尺寸和初始输入称为 PyCharm 实测。跳转仍只接受正整数行号，不增加列跳转或代码编辑。

- 文本始终只读，鼠标选择和复制可用。
- 行号列固定，不因长行横向滚动消失。
- 短文件不保留空白横向滚动范围；长行进入可见区域后扩展范围，保证整行可访问。内容或字体变化时重新度量，保持仍有效的横向阅读位置，内容变短后将旧偏移收回实际范围；选择、焦点和纵向首行不因范围更新改变。
- 工具栏提供自动换行、空白符显示、当前文件搜索和跳转行。
- 文档工具栏按画面从左到右参与 Tab/Shift+Tab 导航：普通文本为换行、空白符、搜索、跳转；模式为原文、对照（仅 Markdown）、预览或格式化、更多；图片为缩小、放大、适应区域。Enter 与 Space 激活当前可用动作，禁用和纯文字项不参与导航；切换显示选项保留按钮焦点，搜索和跳转按动作进入相应输入。
- `Ctrl+F` 在正文顶部打开占一行的查找条，不改变标签身份；查找条显示时正文从其下方开始，关闭后恢复原正文区域。
- 搜索条包含普通文本、区分大小写、全字和正则开关，以及结果数量、上一项、下一项和关闭。
- 查找条固定在正文顶部并占用一整行；输入有效查询后自动定位首个匹配，显示“当前项/总数”，其他匹配保持高亮。`Enter` 定位下一项，`Shift+Enter` 定位上一项，匹配选择与滚动更新后焦点仍在查找框；鼠标或按钮 `Enter` 定位后保留对应按钮焦点。`Tab`/`Shift+Tab` 在输入框、三个开关、上一项、下一项、关闭之间循环，`Esc` 收起查找条并将焦点交回当前正文。中文输入法组词期间不抢占 Enter、Esc 或 Tab。
- 组词开始使未完成查询及其排队导航失效，组词中的文字变化不扫描、不移动正文，结果区清除旧数量；结束后按最终文字查询一次。取消组词回到原查询时复用已完成数量和当前匹配。失焦确认只更新数量及高亮，不抢回焦点或滚动；外部刷新在组词结束后按最新正文统计。关闭或隐藏后的旧组词消息不能恢复查找任务，重复的最终文字通知不清除当前匹配位置。这是已有输入法与异步规则的补齐，不登记为新增 PyCharm 实测。
- 前后切换从当前匹配的对应边界继续，不重复停在当前项；零宽正则在文本首尾仍能循环。无结果显示 `0/0`，无效正则或超时在查找条内说明原因，不关闭输入或修改正文。同一正文、查询与开关下连续定位复用结果计数；正文或查询变化后重新统计，重新打开相同查询时保留当前匹配（当前匹配失效时定位首项）。
- 普通文本计数与定位采用同一大小写和全字边界规则；被全字条件拒绝的候选不遮挡后续有效匹配。无结果时导航保留正文原选择；关闭后重开相同查询保持当前匹配，下一次导航从其边界继续。视觉稿数量从正文样本计算，默认忽略大小写的 `Git` 为 12 项（包括 `Augit` 内的子串）、全字为 3 项，不能使用固定数字代替查找。
- 查找条采用 PyCharm 的正文顶部占行布局；输入后自动定位首个匹配并显示当前项/总数，其他匹配保持高亮。`Enter` 与 `Shift+Enter` 分别前后定位，`Esc` 收起查找条并保留当前位置。
- 大文档和正则的计数、定位在后台执行，输入、正文滚动和关闭不等待扫描。新查询先清除旧数量，低于 150 毫秒不显示加载提示，超过后在原结果区显示“正在搜索…”；完成后原位显示数量或原因。已有计数的连续定位继续复用数量，按 Enter/上一项/下一项的输入顺序定位；换查询、开关、正文或显示模式时取消旧任务和旧方向队列。隐藏文档、关闭查找或销毁标签立即使旧结果失效，不再改变选择、滚动或焦点；再次显示时恢复查找词与开关，并在需要时重新计算。加载与超时视觉稿见[查找进行中](ux-mockups/text-viewer.html?find-state=loading)和[查找超时](ux-mockups/text-viewer.html?find-state=timeout)。
- 查找条占正文顶部一行，按实际字高扩展；输入框、当前项/总数、开关和前后导航均位于同一行，正文从查找条下方开始。输入后自动定位首项，`Enter`/`Shift+Enter` 前后定位，`Esc` 收起并保留正文位置。修改字体后保留查询、输入选择和焦点。
- 文件外部变化后尽量恢复滚动位置和选择；被删除时替换为删除状态页。
- 普通文本的同类型外部更新复用现有正文控件，保留选择方向、横向与纵向滚动、当前输入焦点、换行和空白符开关。新内容变短时将位置限制在有效范围，选择端点不得停在 UTF-8 字符内部。查找输入及开关保持，结果数更新，下一项从原查找位置继续；相同内容的重复通知不重写正文。

状态：正常、加载、空文件、外部更新、文件删除、读取失败。

### 7.3 Markdown

视觉稿：[Markdown 预览](ux-mockups/markdown-preview.html)。

- 从文件树打开时默认预览模式；用户切换模式后在当前会话记忆该选择。
- 原文、预览和左右对照使用编辑区右上角三段式切换，不创建三个标签。
- 三段式切换沿用 PyCharm 紧凑图标控件：26px 按钮步长、36px 工具栏高度；原文为四条横线，对照为左侧短横线加右侧窄圆角框，预览为圆角图片框。只有当前按钮显示内缩选中底色，整组不增加外框。
- 左右对照分隔位置允许拖动，模式切换不丢失各自滚动位置。
- 拖动保留鼠标按下处的偏移，按下不跳动；越过左右边界时停在对应最小栏宽。重复移动到同一实际位置不重排正文。松开、Esc、失去捕获、系统取消、切出对照、隐藏或关闭结束拖动，保留已显示比例；拖动中的 Esc 只结束拖动，不同时收起查找条。窗口过窄时暂时夹紧宽度，恢复后沿用原比例。
- 预览加载期间保留原文或上一次预览，只在预览侧显示局部加载状态。
- 隐藏的 Markdown 标签不预热或并发创建预览；切回标签后才恢复该标签上次选择的模式。
- 相对文件链接在 Augit 标签中打开，外部链接交给系统前保持当前页面。
- 阻止的图片或链接在原位置显示紧凑错误，不使整个预览失败。
- 同一文件的三模式切换保留原文选择、预览阅读位置和对照比例；重复点击当前模式不重新加载。切到原文只是改变显示模式，关闭文件标签才结束该文件的预览会话。
- 外部更新时复用原文控件，保留选择、滚动、查找和当前模式；预览只应用最后一次有效渲染。后台标签不因更新创建预览，也不覆盖前台状态提示。
- 加载超过 150ms 时，在预览区域顶部显示紧凑提示，原文或旧预览继续可见。失败提示给出当前原因，用户可再次点击预览重试；被阻止链接保留原标签文字和原因，不使用跳到页首的空锚点。
- 三模式正常切换的参考记录见 `PY-MARKDOWN-MODES-01`；精确位置保持与异步时序是 Augit 验收约束，不能标记为 PyCharm 已实测细节。

状态：渲染中、正常、远程图片加载、资源阻止、解析失败、超限。

### 7.4 JSON

视觉稿：[JSON 格式化](ux-mockups/json-preview.html)。

- 原文和格式化使用双段式切换，均只读。
- JSON 双段式切换复用 Markdown 模式控件的尺寸、对齐和状态规则，图形按对应场景的 PyCharm 图标逐项复原。
- 格式化结果使用两空格缩进并保留属性顺序。
- 格式错误时默认显示原文，并在顶部显示准确行列与错误文字；点击错误可以定位对应行。
- 错误行列从 1 开始，列按 Unicode 标量计数（代理对算一个字符），不显示 UTF-8 字节偏移。错误条可通过 Tab 到达，Enter 或 Space 与单击执行相同定位；定位后焦点进入原文。错误条随界面字号换行，不挤占或覆盖路径栏与查找条。
- 格式错误时保留“格式化”按钮的位置并禁用，不能把原文当作格式化结果；修复后恢复可用。错误条自身获得焦点时被外部修复隐藏，焦点回原文；其他焦点不变。
- 切换格式化模式不写回文件，不显示保存按钮。
- 查找基于当前可见的原文或格式化文本。切换模式保留查找词与开关，立即更新结果数，并从新显示文本的起点继续查找；重复点击当前模式不重置查找位置。同一格式化内容的连续查找复用显示结果，不重复格式化全文。
- JSON 同类型外部更新复用原文与格式化正文，保留当前模式、阅读位置和查找状态。文件变为无效 JSON 时显示最新原文并更新错误原因；只有焦点原在格式化正文时才转交原文，后台文件或查找输入不抢焦点。恢复有效后继续保留原文模式，直到用户主动切换。

状态：格式化成功、格式错误、超限、非法 UTF-8。

### 7.5 图片与不可预览文件

视觉稿：[图片预览](ux-mockups/image-preview.html)与[不可预览文件](ux-mockups/file-limit.html)。

- 支持图片居中显示，工具栏左侧依次为缩小、缩放比例、放大和适应区域，右侧显示像素尺寸、类型与文件大小。
- 透明棋盘格只覆盖图片实际矩形范围，图片外围保持主题画布纯色；不添加编辑工具。
- 初次打开与“适应区域”完整显示图片，四边至少留 32px，不放大小图；极大图片可缩小到 10% 以下以保证适应。手动缩放使用 10%、25%、50%、75%、100%、125%、150%、200%、300%、400%、600%、800% 步进；比例以图片物理像素计算。
- 放大超过视口后，可拖动图片、用方向键移动；滚轮上下移动，Shift+滚轮横向移动，Ctrl+滚轮按相同步进缩放。移动限制在实际图像边缘，较小的方向保持居中；适应区域重新居中。操作仅影响图片，按钮缩放保留按钮焦点；隐藏、取消捕获或关闭时解除拖动。
- 高精度滚轮不足一档的 Ctrl 缩放增量先累计，达到完整档位后才缩放；单次多档输入合并为一次比例更新。普通滚动保留小于一像素的余量，原生横向滚轮与触控板横向输入可移动图片。切换滚轮模式、按钮动作、拖动、隐藏或替换图片时清除未完成输入，隐藏视图不接受旧输入；不为滚动新增计时器或后台任务。这是 Augit 的输入适配，不声称为 PyCharm 细小滚动实测。
- 同一有效图片的外部更新复用预览窗口、保留手动缩放与仍有效的位置，适应模式按新尺寸重新计算；即使大小不变也重新解码。更新后损坏或不再支持时显示准确的信息页，不能保留旧图片冒充最新内容。这些操作是 Augit 图片查看的适配规则，不登记为 PyCharm 直接实测。
- 图片解码在后台执行，期间可以切换标签、输入和关闭窗口；后续更新使旧请求失效，关闭后晚到位图必须释放。刷新超过 150ms 时只在图片画布中心显示“正在读取文件…”，不改变工具栏、标签或面板尺寸；完成后撤去提示，隐藏图片不能抢占当前文档和焦点。加载态参照 `image-preview.html?image-state=loading`。
- 图片缩小时对相邻像素进行平滑采样，避免斜边锯齿和高频纹理跳变。平滑图像在后台生成，期间先显示快速采样结果，完成后原位更新；移动、缩放和关闭不等待计算。100% 时保留原像素，不额外锐化或改动图片内容。
- 超限、解码失败、GIF、WebP 和其他二进制使用信息页，显示类型、大小和完整路径。
- 信息页唯一主要动作是用系统默认程序打开。

### 7.6 Commit 与 Changes

视觉稿：[提交工具窗](ux-mockups/commit-changes.html)、[提交空态](ux-mockups/commit-empty.html)与[Changes 右键菜单](ux-mockups/changes-context-menu.html)。

- 每组文件按显示文件名自然顺序排列；显示文件名相同的条目再按完整相对路径稳定排序。

- 按 `Enter`、双击文件或执行“显示 Diff”时打开并激活唯一工作区 Diff 标签；后续 Changes 选择持续更新该标签，关闭后解除跟随。
- 用户修改文件后保留复选状态，仅更新状态标记和 diff 内容版本。
- Commit 与 Commit and Push 固定在底部，滚动长文件列表时仍可见。
- 字号改变时，标题、Changes 行、Amend 和提交动作按实际字高扩展，工具图标和复选框保持固定尺寸。底部两个文字动作放不下时按原顺序排成两行，设置图标留在第一行右侧；输入框至少保留提示行和一行可输入正文，必要时减少列表高度。上一次提交在空间不足时只显示原有历史图标并保留完整悬停说明，数量使用剩余宽度省略。更改字号或面板尺寸不重查 Git，不清空草稿、勾选或当前 Diff；错误提示切换不重新布局。这是现有字号设置的适配，不登记为 PyCharm 大字号实测。
- 空态复用同一提交布局；列表区域不足以同时容纳两行说明时保留“没有待提交的更改”，收起次要说明，避免覆盖 Amend 或输入框。
- Amend 勾选后读取上一次提交信息；取消后恢复用户尚未提交的原文本。
- 校验错误显示在提交信息附近，焦点留在提交信息，不弹出全局错误框。
- 提交校验或 Hooks 失败复用输入框内上方的提示行，使用错误文字和危险色；长原因可悬停完整阅读，不挤动 Changes、Diff 或提交动作栏。保留提交草稿与文件勾选，状态刷新不清除原因；用户修改提交信息或再次提交时清除旧提示。等待期间用户已把焦点移到其他区域时，失败反馈不得抢回焦点。该局部适配不登记为新增 PyCharm 实测；视觉稿见[校验失败](ux-mockups/commit-changes.html?commit-state=validation)和[Hooks 失败](ux-mockups/commit-changes.html?commit-state=hook-failure)。

状态：加载、无变化、有 Changes、有 Unversioned Files、校验失败、Hooks 失败、提交中、成功、冲突。

### 7.7 工作区 Diff

单双栏模式采用设计系统第 8.4 节的统一分段控件；两个按钮各自可获得键盘焦点，Tab/Shift+Tab 按可见顺序移动，Enter 或 Space 激活当前按钮。忽略空白仍是独立开关。重排正文期间保留工具栏按钮焦点，用户主动转移焦点后不得抢回。

视觉稿：[工作区 Diff](ux-mockups/commit-diff.html)与[Diff 局部加载](ux-mockups/diff-loading.html)。

- 首次单击 Changes 文件只改变列表选中，不创建、不激活 Diff 标签；编辑区中的普通文件、标签和滚动保持不变。
- 按 `Enter`、双击文件或执行“显示 Diff”时，在编辑区创建或复用并激活唯一工作区 Diff 标签；双击不固定原文件，后续选择持续更新该标签。
- 已有 Diff 标签但当前显示普通文件时，新的列表选择只在后台更新该标签；Diff 已激活时在同一编辑区域原位更新。
- 第一次请求加载时保留旧 Diff 正文约 200 毫秒，随后在同一正文区域替换为加载状态或新结果；其他区域不变化。
- 顶部工具栏左侧依次为上一处、下一处、搜索、上一个文件、文件计数和下一个文件；右侧为差异摘要、忽略空白、双栏/单栏和设置。文件箭头围绕文件计数分组，键盘 Tab 顺序与视觉顺序一致。
- 差异数量按连续变更块计算；同一次替换的删除行与新增行属于同一处差异，不按排版后的行数计数。未修改的上下文或不同补丁段分隔变更块，无换行标记不拆分变更块。单栏与双栏保持相同数量，前后改动定位到当前布局中对应块的首行；首次点击“上一处”定位最后一块，首次点击“下一处”定位第一块。历史和引用比较沿用同一规则。
- 双栏文件栏明确标注左侧基准和右侧当前版本，目标信息对齐右正文起点；单栏把来源和目标上下排列，路径跟随来源显示。两种模式均明确只读身份，完整路径保留在悬停说明。仅重排 Diff 文件信息与正文，不移动工具栏、标签、Changes 或底部工具窗口。
- 工作区 Diff 到达当前文件首/尾变更块后，再按同方向差异箭头只显示“再次点击可进入上一个/下一个文件”；再次按同方向才切换相邻文件。前往下一文件定位第一块，返回上一文件定位最后一块。第一次提示不发起查询、不移动正文，不在本文件内循环。对应实测场景 `PY-DIFF-BOUNDARY-01`。
- 跨文件同步 Changes 选中路径、标签身份和文件计数，保留复选、提交草稿、其他标签、工具窗口和几何。跨文件查询/排版期间禁用差异箭头，文件箭头和 Changes 仍允许改选；旧结果不能覆盖新选择或恢复旧定位。
- `Esc` 关闭边界提示并撤销待跨文件状态；改变方向、选择文件、切换显示模式、隐藏/关闭 Diff、重新加载或改变窗口布局同样撤销。列表首尾没有相邻文件时只显示已到首/尾的局部说明，不循环整个文件列表。后两类边界细节属于 Augit 稳定性规则，不冒充 PyCharm 异常路径实测。
- 双栏 diff 中间行号与变更连接区固定，左右正文同步垂直滚动。
- 工作区 Diff 双栏正文左右留白为 13px，行号中栏左右各留 7px；中栏至少 84px，按当前等宽字体和当前补丁中最长行号实际度量。改变等宽字号时只重排当前正文与行号，不重新请求 Git、不清空提交草稿或文件选择。
- 二进制或超限 diff 使用摘要页替代正文，不改变 Commit 工具窗口。
- Markdown 与 JSON 的默认 Git 页面仍显示磁盘真实文本 diff，可从工具栏打开修改后预览。

状态：临时标签、加载、正常、空差异、重命名、二进制、超限、失败、过期结果被丢弃。

- 提交列表顶部有文本或哈希搜索，以及分支、用户、日期和路径筛选。

### 7.9 文件历史、Blame 与引用比较

视觉稿：[文件历史](ux-mockups/file-history.html)、[Blame](ux-mockups/blame.html)与[引用比较](ux-mockups/git-compare.html)。

- 文件历史复用 Git 历史工具窗口，将路径筛选固定为当前文件，并显示清除入口。
- 文件历史提交列表按视觉稿从左到右显示作者、日期和提交标题，不沿用 Git 日志的提交图及右置元信息。窄栏在自身区域横向滚动；选择、上下键、分页和返回继续使用同一提交身份，不因列布局改变而重查比较或重建主窗口。
- 进入文件历史时保存日志上下文，包括已生效的组合筛选、尚未执行的筛选输入、页码、提交选择、提交列表纵横滚动、变化文件的折叠/选择/顶部位置、详情显隐与正文位置。普通日志已有路径筛选时也须保存；从一个文件历史切到另一个文件历史不覆盖最初的返回位置。清除文件历史后恢复该上下文，焦点回到可操作的提交列表。快照相同时不重建列表或提交图，进入前尚未完成的详情在返回后重新加载。
- 从文件树首次进入文件历史时，普通日志可能尚未完成任何查询；返回日志后必须按原筛选补查，不能把初始化的空列表当作最终空结果。已成功加载的空日志仍直接恢复，不因没有提交而重复查询。
- 文件历史预览按提交与路径复用已完成或进行中的查询；相同快照刷新不重写正文、不改变阅读位置。改选提交时立即取消旧预览，不能等新详情返回后才使其失效；隐藏工具窗口、清除文件历史和销毁时取消未完成查询，晚到成功或失败均不得回写。重新显示时只补查未完成的预览；失败后再次选择同一提交可以重试。清除文件历史后释放隐藏预览正文。这些规则是 Augit 对已有上下文与异步约束的适配，不登记为 PyCharm 新实测。
- 文件历史右侧复用完整只读比较视图：工具栏按上一处、下一处、查找、差异计数、忽略空白、双栏、单栏、设置排列；顶部文件栏显示父版本、提交版本和相对路径；正文使用与引用比较相同的行号、变更高亮和差异块导航。文件历史不再把 unified patch 当作普通文本显示，显示模式切换复用已加载补丁，不重新调用 Git。
- 点击底部“日志”标签与清除文件历史入口均恢复进入前的日志上下文。隐藏右侧详情时取消未完成的查询和排版，重新显示按当前选择补查；已经完成的比较保留正文、显示模式和阅读位置。右侧比较的 Tab 顺序在当前文件历史工具窗口内经过工具按钮与正文，不进入上方普通文档。
- Blame 在普通文本左侧增加作者与提交信息列，不改变文件只读属性。
- 归属边栏按现有视觉稿分为日期、作者摘要和文档行号三列；与正文使用相同行高，纵向滚动同步，横向滚动不移动归属列。日期和行号在字号变化时按实际字宽扩展，作者在自身列内省略；点击映射始终使用完整提交哈希。
- Blame 查询尚未完成时，切换普通文件或比较标签、关闭目标文件、隐藏历史工具窗口、切换工作区及销毁窗口使旧请求失效。连续发起查询只接纳最后一次；旧成功或失败不能打开标签、显示旧归属或覆盖新状态。Git 查询完成后的正文读取也核对工作区、选择版本与目标路径；已经切走的普通文件可完成后台缓存，但不能重新激活或附加旧归属。
- Blame 顶部沿用视觉稿的右侧“n 行归属”和关闭入口，隐藏普通文档动作。Tab 可到达关闭按钮，Enter 或 Space 关闭后恢复对应文件类型的工具栏，保留当前原文、选择和阅读位置并把焦点交回正文；无效 JSON 的格式化入口恢复显示但保持禁用。查找输入和焦点变化不能关闭 Blame。外部刷新清除旧归属时同步恢复工具栏，保持刷新前的输入焦点。此条细化现有视觉稿和局部更新规则，不登记为新的 PyCharm 实测。
- 点击 Blame 提交定位 Git 历史并选择对应提交。
- 从文件历史中的 Blame 定位提交时恢复日志布局，并解除旧文件路径限定和预览请求；异步完成不再次抢焦点，不恢复旧文件历史页。
- 引用比较复用 diff 编辑标签，并在标签和文件栏明确显示双方引用。
- 文件信息沿用 `PY-DIFF-MODES-01` 的双栏左右、单栏上下结构；顶部一行显示来源与路径，单栏第二行显示目标。查询或排版仍显示旧正文时，文件栏保留该正文的布局；最终模式就绪时一起切换。失败、取消及摘要按当前所选模式显示双方身份，文件栏不进入 Tab 顺序。
- 比较工具栏和文件信息区按当前界面实际行高扩展；字号变大时仅增加工具行和文件信息行高度并同步下移正文，图标尺寸与命中区保持，文字不能被裁切或覆盖。窄宽度下保留既定按钮顺序和局部提示。
- 比较标签先显示文件名，再显示来源与目标引用；三部分独立省略，长文件名或长引用不得挤掉另外两部分。完整 40/64 位提交哈希在标签和文件栏中显示前 8 位，保留 `^`、`~` 祖先后缀；命名引用保持原名。文件栏悬停说明保留双方完整引用与相对路径，实际 Git 查询始终使用完整原值。该收缩方式属于在 Augit 已有布局中的适配，尚未完成 PyCharm 同场景逐像素对照。
- 历史与引用比较遵循第 6 节相同的加载规则：重复点击当前显示模式不排版、不查询；查询期间切换显示模式只改变最终呈现方式。连续切换忽略空白时以最后选项为准，旧查询成功或失败都不得覆盖新的比较。
- 历史与引用比较的差异总数在比较工具栏显示，不通过导航覆盖全局状态栏。箭头定位正文后保留触发按钮焦点，支持继续按 Enter 或空格；Tab 和 Shift+Tab 按工具栏可见顺序经过可操作按钮与正文，再返回标签栏，跳过禁用动作、文件信息、计数、行号中栏和隐藏正文。加载、失败及取消说明保留一个正文焦点位置，使用户仍可从比较区返回标签。此规则不改变第 7.8 节的提交或文件选择语义。
- 历史面板发起引用查询时在自身区域显示“取消比较”，不写入全局“正在生成 diff”提示；完成后隐藏取消入口，比较区自行完成正文排版和局部加载提示的收尾。
- 新引用比较取代尚未完成的历史文件 Diff 查询；用户取消比较后，即使服务晚到返回成功或失败也不得显示结果。关闭已有比较标签，同时取消历史面板为该编辑位置发起的文件或引用查询，旧任务不得重新打开标签；取消比较不取消无关的 Git 写操作。
- 摘要和失败页清空上一份正文的变更导航，前后改动与正文搜索禁用但保留入口；失败原因留在当前比较区域，用户可以重新切换比较选项重试。关闭比较标签取消未完成查询与排版，释放补丁及隐藏正文；仅切到普通文件标签则保留已有比较供返回。
- 比较对话框只列出分支、标签和提交，不显示平台 API 对象。

### 7.11 Stash、Reset、Worktree 与远端

视觉稿：[创建 Stash](ux-mockups/stash.html)、[Stash 管理](ux-mockups/stash-manager.html)、[Reset](ux-mockups/reset.html)、[Rollback](ux-mockups/rollback.html)、[Worktree](ux-mockups/worktrees.html)和[远端](ux-mockups/remote.html)。

- Worktree 和远端使用双栏管理窗口，左侧对象列表，右侧详情和动作。
- Reset 模式必须在同一页面解释 HEAD、索引和工作区的影响；Hard 使用红色确认。
- Reset 按实际字高度量字段、模式说明及按钮；标题和底栏固定，限高时只滚动表单与反馈。字段获得焦点时自动滚入可见区域，错误或进行态不移动整窗和底部动作；模式收起态完整容纳说明，不因原生箭头或滚动条占宽裁切末字。目标输入保留左右内距，点击内距可聚焦且不清除选区；不显示无对应功能的帮助图形。
- Rollback 风险说明按实际字体换行，并为新增或未跟踪文件保留回收站说明；先展示真实只读比较，再由底栏确认。字号放大或窗口限高时，风险说明与比较所在正文可滚动，标题和底栏固定；比较自身继续独立滚动文本，Tab 进入被裁切的比较工具或正文时自动滚入可见区域。窗口和焦点变化不重查 Git、不替换当前比较。以上属于既有字号、模态与危险确认规则的落实，不登记为新增 PyCharm 实测。
- Worktree 详情标题显示当前分支，正文显示路径、干净状态和内置终端占用；条件不满足时禁用移除并显示具体原因。
- 远端只管理名称、Fetch URL 和 Push URL，不提供托管平台账号或项目选择。
- 远端管理按实际字高排布标题、列表、字段和动作。窗口高度受限时只滚动右侧详情，工具栏、左侧列表与底部关闭保持固定；Tab 进入被裁切字段或按钮时自动滚入可见区域。失败说明在详情内换行并可滚动查看，不覆盖底部动作；不显示无对应功能的帮助占位。

### 7.12 Clone、Push 与本地 Git 操作反馈

视觉稿：[Clone](ux-mockups/clone.html)、[Push](ux-mockups/push.html)、[Push 无远端](ux-mockups/push-no-remote.html)、[Git 操作进行中](ux-mockups/operation-progress.html)和[Git 操作反馈](ux-mockups/operation-result.html)。

- Clone 初始 URL 与目录为空并显示占位说明，浅克隆默认不勾选，深度保留 `1` 但禁用；勾选后才启用并校验正整数。缺少必填项或深度不合法时不调用 Git，提示原因并聚焦对应输入。
- Clone 标题与底部动作固定，字号放大时按真实字宽、字高排布；浅克隆行放不下时将深度与单位一起换至下一行。错误在正文换行并可滚动查看，聚焦字段时自动滚入视口，错误出现或消失不能移动整窗及底栏按钮。
- Clone 初始焦点在 URL；Tab/Shift+Tab 按版本控制、URL、目录、浅克隆勾选、启用的深度、取消、克隆、关闭循环。输入中的 Enter 执行克隆，Esc 关闭；输入法组词期间不抢占按键，下拉框展开时保留自身确认/取消语义。
- Clone 进行中冻结表单和确认按钮，取消先请求 Git 结束，结束前不能重新提交或把取消显示为完成；失败或确认取消后保留输入与勾选并允许重试，成功返回实际仓库路径并关闭。宿主销毁时取消在途操作，拒绝晚到结果。
- Push 对话框显示本地引用、目标远端引用和待推送提交列表。
- Push 提交行使用统一自绘勾形标记，不使用文字字形充当图标；行高按实际界面字高扩展，单击只选中提交，不改变整个引用的推送范围。选中态优先于悬停，失焦保留中性选中背景；悬停不请求 Git 或重建内容，隐藏、禁用及销毁清除过期状态。
- Push 标题和底部动作固定，右侧说明与错误在详情区域内滚动；左侧列表独立滚动。没有远端时保留“定义远端”及禁用的推送标签选项，推送禁用；窗口限高时必须为标签选项预留空间，先缩短正文，不能压住底栏。字号适配属于现有规则的落实，不登记为新增 PyCharm 实测。
- Push 预览未完成或没有待推送提交时不允许推送。进行中阻止重复提交，取消等待 Git 任务结束；晚到成功不能覆盖用户的取消。失败与取消保留引用、提交列表和已转移的焦点，并允许重试；成功关闭并恢复主窗口原焦点。对话框关闭或销毁后拒绝晚到结果。
- 点击“定义远端”打开嵌套远端管理窗口；关闭后只重新读取 Push 预览，不创建第二个 Push 窗口，不改变提交列表、草稿或主窗口布局。预览完成后焦点回到提交列表（若定义远端按钮因状态变化隐藏或禁用，则回到列表）；远端窗口关闭或销毁后的晚到结果不得回写 Push。
- 不显示 Force Push 开关或平台账号入口。
- 操作开始后确认按钮变为进行状态，并显示取消；不能重复提交同一操作。
- 失败原因显示在当前对话框或触发区域，关闭后不保留 Git Console 或操作历史。
- 图形 Git 命令需要交互输入时直接失败并说明原因，不提供原命令复制或终端重试入口。

## 9. 关键状态机

### 9.1 Diff 状态机

`未选择 → 已选择 → (Enter/双击/显示 Diff) → 等待阈值 → 加载中 → 已显示`。

- `未选择`：编辑区保持当前正式文件或稳定空状态。
- `已选择`：只保留列表选中和路径意图，不创建 Diff、不请求正文；已有 Diff 标签时允许在后台更新请求。
- `等待阈值`：用户明确打开 Diff 后创建或复用临时标签，150 毫秒内不显示闪烁动画。
- `加载中`：仅 Diff 标签正文显示加载；列表、工具栏和其他标签不变化。
- `已显示`：原位替换加载内容。
- 新选择到达：递增请求版本并进入新的等待状态；旧结果不得覆盖。
- 相同选择到达：保持已显示，不进入加载。
- 请求失败：进入局部失败状态，保留选择和周边结构。

### 9.2 Git 刷新状态机

`空闲 → 合并事件 → 查询快照 → 比较快照 → 无变化/增量应用 → 空闲`。

- 多个文件系统与 `.git` 事件必须合并。
- 查询期间不清空现有列表。
- 无变化直接回到空闲。
- 有变化仅更新差异项，并决定当前 diff 是否失效。
- 查询失败显示非阻塞错误，保留上一个已知界面但明确标记不是最新状态。

### 9.3 Git 写操作状态机

`可执行 → 确认 → 进行中 → 成功/失败/冲突/取消中 → 读取最新事实 → 稳定状态`。

- 进行中禁用重复触发，显示取消和当前动作。
- 成功后刷新相关文件、Changes、分支和历史。
- 失败后保留用户输入并显示脱敏原因。
- 冲突后进入操作会话，不把冲突包装成普通失败。
- 取消后等待本机 Git 停止，再读取真实仓库状态。

### 9.4 工具窗口状态机

- 左侧：`折叠 ↔ 项目 ↔ 提交 ↔ 搜索`。
- 底部：`折叠 ↔ Git 历史 ↔ 终端`。
- 左侧和底部状态独立。
- 切换只替换对应区域，不重建编辑器和另一个工具区域。

## 10. 空、错、禁用与危险状态

### 10.1 空状态

- 空状态使用一句主说明和必要的一个动作，不使用大插画。
- 无 Changes：显示“没有待提交的更改”，保留提交工具窗口骨架。
- 无历史：显示“仓库还没有提交”，保留引用树和筛选栏。
- 搜索无结果：显示“未找到结果”，输入框和查询保持。

### 10.2 错误状态

- 错误归属到发生区域，不优先使用全局消息框。
- 错误必须说明发生了什么、哪些状态未改变以及用户可以做什么。
- Git 命令输出脱敏并限制长度，不提供 Git Console 或持久化日志。
- 同一错误在外部状态未变化时不重复弹出。

### 10.3 禁用状态

- 禁用控件必须有可发现原因，例如悬停说明或相邻文字。
- 工具栏中暂时不可用的稳定命令可以禁用并保留位置。
- Git 操作会话中“不适用于当前状态”的 Continue、Skip 和 Abort 必须隐藏。
- 产品明确不支持的能力不得以禁用占位出现。

### 10.4 危险状态

- Reset Hard、Rollback、删除分支或标签、删除 Stash、移除 Worktree 必须显示具体影响。
- 确认按钮使用动作名称，例如“确认 Reset Hard”，不得只写“确定”。
- 未跟踪文件删除必须明确说明进入 Windows 回收站。

## 11. 可访问性与可用性

- 交互控件具有可读名称，图标按钮具有悬停说明和辅助技术名称。
- 选中、修改、错误和冲突不能只靠颜色，必须配合图标或文字。
- 键盘焦点始终可见。
- 动态结果使用非打断式状态通知；操作失败使用明确错误通知。
- 列表虚拟化后仍保持正确的键盘顺序与当前项。
- 深色和浅色主题下正文、次要文字、选中行和 diff 块均保持可读对比度。

## 12. 视觉与交互验收标准

### 12.1 页面覆盖

每个下列页面或关键状态必须具有浅色视觉稿并在真实应用中可到达：打开工作区、初始化仓库、项目、项目右键菜单、普通文本、Markdown、JSON、图片、不可预览文件、Commit、Commit 空态、Changes 右键菜单、工作区 diff、Diff 局部加载、Git 历史、Git 历史右键菜单、文件历史、Blame、引用比较、分支与标签、Smart Checkout、创建 Stash、Stash 管理、Reset、Rollback、Worktree、远端、Clone、Push、Push 无远端、Git 操作进行中、冲突列表、三栏冲突、快速打开、快速打开空态、全仓搜索、搜索截断与超时、终端、关闭运行中终端、设置、Git 不可用和 Git 操作结果。

全部页面还必须在深色主题下通过结构、文字、选中态、Diff 与弹层对比度检查；深色主题使用相同页面和状态，不另外创造业务分支。

### 12.2 稳定性

- 首次单击 Changes 文件不创建 Diff；按 `Enter`/双击打开后，左侧工具窗口和底部工具窗口的位置在加载前后不得变化。
- 没有 Diff 标签时同一文件连续单击十次不产生 diff 请求；已有 Diff 标签时连续选择只产生当前请求并去重。
- 快速连续选择三个文件时，普通文件仍保持在编辑区，已有 Diff 标签最终更新为第三个文件；Diff 已激活时原位显示第三个文件，过期结果不得闪回。
- Git 无变化刷新十次不重建列表、不改变选择、不重新加载 diff。
- 外部改变当前文件后在 500 毫秒内更新当前 diff，保持工具窗口、标签和滚动位置。
- 外部改变无关文件时当前 diff 不进入加载状态。
- 选择 Git 提交后仅右侧详情区更新，提交列表不闪白。

### 12.3 视觉一致性

- 主框架区域、尺寸层级和信息密度与视觉稿一致。
- 工具按钮可见图标 16 像素，命中区域至少 28 × 28 像素，同行间距一致。
- 左侧 Git 历史竖向工具栏完整存在，每个图标都有有效命令和悬停说明。
- 不出现产品规格排除的按钮、菜单、标签、设置或空占位。
- 功能图标必须按 PyCharm 的可见几何、比例、线宽、填充、位置、颜色和状态自绘复原；不使用 JetBrains 商标、PyCharm 产品标志、字体文件或官方图标资源文件。Augit 自有品牌标记保留为唯一品牌例外。

### 12.4 自动化要求

新增或修改界面逻辑时至少覆盖：

- 快照相等不更新。
- 增量更新保持选择和滚动。
- 相同 diff 请求去重。
- 连续选择丢弃过期结果。
- 加载、失败和取消均只更新局部区域。
- Git 历史提交详情的异步版本保护。
- 工具窗口互斥与分隔位置持久化。
- 所有图标入口都有命令、启用条件和悬停说明。

### 12.6 连续工作流验收

单个场景截图只能证明某个稳定帧存在，不能证明页面跳转、焦点归属、局部刷新和返回路径正确。以下工作流必须在真实 Win32 应用中按顺序执行；每一步都要记录动作、目标窗口、选中项、焦点、滚动位置和允许变化的区域。任何一步失败，都不能用后续截图覆盖。

| 工作流 | 必须执行的连续动作 | 每一步必须保持或验证的状态 |
| --- | --- | --- |
| `workspace-to-document` | 打开工作区 → 单击文件 → 再次单击其他文件 → 双击文件 → `Enter` 打开另一个文件 → `Ctrl+W` 关闭标签 | 单击只改变树选择；双击或 `Enter` 才创建正式标签；项目展开、标签顺序和底部工具窗不被重建；关闭后激活相邻标签。 |

| `history-to-detail` | 打开 Git 历史 → 单击提交 → 单击同一提交 → 单击另一提交 → 展开目录 → 双击叶子文件 → 返回历史 | 提交列表不重建、不跳回首行；相同提交不重复请求；已有历史比较随提交和文件选择更新，普通文档前台不抢占；目录只能展开，叶子文件才打开 Diff；返回后保留提交、筛选和滚动。 |
| `background-tab-close` | 打开普通文件 A、B → B 滚动并在树或查找框中保持焦点 → 中键/关闭叉关闭后台 A → 比较前台时关闭最后一个普通标签 → 关闭比较返回 | 后台关闭只移除目标标签并释放其视图；按下关闭叉不抢焦点，移出目标或取消捕获不关闭文件；当前正文、查找内容、树选择、滚动和比较请求不变，最后一个后台文件关闭后不显示空白页覆盖比较。 |
| `document-read-switch` | 延迟读取普通文件 → 切到其他文件、工作区 Diff 或引用比较 → 释放读取 → 切回；再验证读取期间改选项目树、关闭当前或后台标签 | 晚到文件只布局自己的隐藏视图，不切走当前正文、不抢焦点、不覆盖新状态；已关闭标签不重建，后台关闭造成索引前移不影响当前请求；比较关闭返回尚未就绪的普通文件时保留读取占位。 |
| `restore-during-input` | 恢复活动文件时延迟读取 → 打开比较、改选树行或打开其他文件并查找 → 释放读取并等待恢复结束 | 恢复任务不二次激活原文件，不覆盖新选择、查找输入、焦点和状态栏；无用户介入时仍正常恢复活动文件和父目录选择，后台标签保持按需加载。 |
| `tool-window-switch` | 项目 → 提交 → 项目 → Git 历史 → 终端 → Git 历史 → 折叠底部工具窗 → 再次打开 | 左侧和底部状态独立；终端与 Git 历史互斥；编辑标签、正文滚动和另一工具区不变；再次打开恢复上次分隔位置。 |
| `popup-and-modal` | 打开分支弹层 → 搜索引用 → 打开二级动作 → `Esc` → 打开设置 → 切换主题预览 → 取消 → 打开危险操作确认 → 取消 | 非模态弹层关闭后恢复原选择、滚动和焦点；设置取消恢复原设置；危险确认取消不执行 Git、不刷新仓库。 |
| `operation-feedback` | 触发 Git 写操作 → 进行中 → 取消或等待失败 → 查看局部结果 → 关闭结果 | 进行中禁用重复动作；取消等待本机 Git 停止；失败只更新所属区域并说明事实；关闭后不保留 Git Console、命令历史或脱敏输出。 |
| `external-change` | 打开文件或 Diff → 从外部修改无关文件 → 从外部修改当前文件 → 从外部改变 Git 状态 → 回到当前标签 | 无关变化不触发当前 Diff 加载；当前文件变化只更新当前正文或 Diff；Git 状态变化只增量更新相关列表；标签、选择、滚动和分隔位置保持。 |

连续工作流的自动化证据至少包括：动作顺序、请求计数或版本号、窗口句柄/焦点句柄、选中路径、滚动位置、工具窗口可见性和最终截图。`PASS=42`、进程正常退出或单页截图不能单独证明连续工作流通过。

## 13. 实施优先级

1. 先修复 Changes 单击错误打开 Diff、重复刷新和过期结果覆盖；固化“单击选择、Enter/双击打开”的状态机。
2. 再补齐 Git 历史左侧竖向工具栏及其现有能力映射。
3. 按本文统一主框架、工具窗口、标签、工具栏、列表、弹层和对话框。
4. 逐页完成产品规格内的全部视觉状态。
5. 最后执行浅色、深色、不同窗口尺寸、键盘导航和自动化回归。

未经以上稳定性修复，不得继续通过增加装饰细节掩盖状态转换问题。
