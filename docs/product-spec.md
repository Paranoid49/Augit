# Augit 产品规格

## 1. 产品定位

Augit 是供 100% 外部 AI 协作开发场景使用的轻量桌面工具。它不接入任何 AI，也不负责生成代码。代码和文档由外部 AI、脚本或人工修改，开发者在 Augit 中浏览项目、检查变化并操作 Git。

轻量优先是 Augit 的最高产品原则。

Augit 的普通文件查看器不提供编辑和保存功能。用户主动执行 checkout、merge、reset、rollback 等 Git 操作时，允许本机 Git 修改工作区，这不属于普通文件编辑功能。三栏冲突解决器的结果区，是 Augit 唯一允许用户直接编辑并保存文本的地方。

## 2. 支持环境与性能目标

- 支持 Windows 10 22H2 x64 和 Windows 11 x64；Windows 11 跟随微软仍受支持的正式版本。
- 不支持 32 位、ARM64、Windows Server、Windows 预览版、网络共享目录和远程文件系统。
- 基准机器为 8 核 CPU、16 GB 内存和 SSD，且不得存在 E-SafeNet 等第三方进程注入。受注入影响的结果只能作为诊断数据，不能作为验收结论。
- Release、win-x64、非 self-contained 发布版优先争取冷启动到界面可操作不超过 1 秒；该数值是性能目标，不以牺牲界面响应、稳定性或视觉还原为代价，也不作为阻止交付的硬门槛。
- 文件树、普通文本和 Git 核心界面的 Working Set 目标为「尽可能少」：主进程与承载主界面的 WebView2 进程树都计入，不再以 100 MB 为门槛（理由与实测见 6.1）。超出时必须记录增量、定位可回收资源并继续优化，但不以牺牲界面响应、稳定性或视觉还原为代价。
- Markdown 预览、内置终端和冲突解决器按需加载，必须单独记录增量内存并在关闭后释放资源。
- 外部文件和本地 Git 状态变化在 500 毫秒内反映。Augit 不后台 fetch 或轮询远端状态。
- 后台空闲时不持续扫描仓库，不明显占用 CPU。
- 10 万文件和 10 万提交规模下，文件树和提交历史按需加载。
- 再次打开同一目录时，在 1 秒内激活已有窗口并退出新进程。

具体测量口径和资源回收标准见[架构说明](architecture.md)；界面结构和视觉规则见[UX/UI 规格](ux-spec.md)及[统一设计系统](design-system.md)。

## 3. 工作区与文件浏览

### 3.1 工作区与文件树

- 一个窗口只打开一个目录；同一目录不重复开窗口。
- 不同仓库和 Git worktree 可以分别打开窗口。
- 允许打开非 Git 目录，并由用户显式初始化仓库。
- 普通文件树隐藏 `.git`，其他点文件正常显示。
- 目录按需展开；被 `.gitignore` 忽略的目录仍显示，但全文搜索默认跳过。
- 文件树先显示目录、再显示文件，同组按 Windows 风格、不区分大小写的文件名自然顺序排列。
- 文件树单击文件只改变选择，不打开标签；双击文件或在选中文件后按 `Enter` 才打开。单击目录左侧展开标立即展开或折叠目录，双击目录名称也切换展开状态。
- 不递归展开目录符号链接或目录联接。
- 普通文件符号链接可以查看本机固定磁盘上的工作区外目标，但界面必须醒目显示解析后的真实目标路径；目标位于网络共享或远程文件系统、目标不存在或形成循环时拒绝读取。
- 外部变化自动加载磁盘最新版本，并尽量保持标签、选择和滚动位置。
- 最多保存最近展开的 50 个目录；再次打开工作区时，先让窗口进入可操作状态，再分批异步恢复这些目录，不递归扫描，忽略不存在或越过工作区的路径。
- 文件树右键菜单提供复制路径、在资源管理器中定位、在外部终端打开和刷新；文件历史能力交付后再增加文件历史入口，不显示不可用的占位项。

### 3.2 普通文件查看

- 支持多标签、行号、复制、当前文件搜索、跳转行、自动换行和空白符显示。
- 文本文件上限为 10 MB；超过上限不读取正文，只显示信息并允许用系统默认程序打开。
- 文本只支持 UTF-8，可带或不带 BOM。不支持 GB18030、UTF-16、编码猜测或手动切换编码。
- 非法 UTF-8 文件明确提示“文件不是有效的 UTF-8”，不显示乱码、不修改文件，并允许用系统默认程序打开。
- 图片预览只支持 PNG、JPEG/JPG 和 BMP，单个文件上限为 25 MB，解码后上限为 2500 万像素。
- 图片超过文件大小或解码像素上限、解码失败时只显示文件信息，并允许用系统默认程序打开。
- GIF、WebP 和其他二进制文件只显示类型、大小和路径，并允许用系统默认程序打开。
- 除已识别的受支持图片外，文件分类先识别其他已知二进制签名和内容中的 NUL 字节，命中时按二进制处理；其余文件按文本执行严格 UTF-8 校验。
- 文件被删除、重命名或替换时显示准确状态，不保留失效内容冒充最新版本。

### 3.3 搜索与快捷键

- 文件名搜索和全仓文本搜索按需调用随程序附带的 ripgrep，不建立后台索引。
- `Ctrl+P` 文件名搜索始终遵循 `.gitignore`，被忽略的文件仍可从文件树打开。
- 全仓搜索默认遵循 `.gitignore`，可以选择包含忽略文件；`.git` 始终排除，即使选择包含忽略文件也不搜索。
- 当前文件搜索和全仓搜索默认按普通文本匹配，并提供区分大小写、全字匹配和正则表达式开关；不提供文件类型筛选或复杂搜索模板。
- `Ctrl+P` 最多展示最相关的 100 个文件。
- 全仓搜索最多展示 1000 条结果；发现第 1001 条时停止搜索，并提示“结果超过 1000 条，已停止搜索，请缩小范围或使用更准确的关键词。”
- 单次搜索最长 15 秒，用户可以随时取消；超时和取消后必须结束 ripgrep 进程。
- 固定快捷键为：`Ctrl+P` 快速打开文件、`Ctrl+Shift+F` 全仓搜索、`Ctrl+F` 当前文件搜索、`Ctrl+G` 跳转行、`Ctrl+W` 关闭当前标签、`F5` 刷新文件树、`Esc` 关闭浮层或取消搜索。
- 不提供自定义键位、键位市场或其他编辑器兼容层。

## 4. 专用预览

### 4.1 Markdown

- 从文件树打开时默认显示渲染结果，可切换原文、预览和左右对照。
- 支持标准 Markdown、表格、任务列表、删除线和自动链接，不支持 Markdown 中的原生 HTML，HTML 标签按普通文本显示。
- 当前文档的标题锚点在预览内跳转；工作区内的相对文件链接在 Augit 只读标签中打开，指向 Markdown 的链接可以继续定位锚点。
- 相对图片和文件链接在路径规范化并解析符号链接后必须仍位于工作区内，越界时不加载并明确提示。
- 允许在用户打开 Markdown 预览时加载 HTTP 或 HTTPS 远程图片；HTTP、HTTPS 和邮件链接交给系统处理，绝对本地路径、越过工作区的路径和未知协议一律阻止。
- Markdown WebView 不注册宿主对象，页面不能调用 Augit、Git 或本地文件能力。
- 首版不支持 Mermaid 和数学公式。
- 从 Git 改动中打开时默认展示磁盘真实文本 diff，可额外查看修改后预览。

### 4.2 JSON

- 从文件树打开时默认格式化展示，可切换原文和格式化结果。
- 使用严格 JSON 规则和两空格缩进，保持属性原有顺序，不自动排序。
- 不接受注释和尾逗号；格式错误时显示具体行列位置并展示原文。
- Git diff 始终基于磁盘真实内容。
- 所有格式化只改变显示，绝不写回磁盘。

## 5. Git 能力

Git 命令语义和操作状态以 IntelliJ IDEA 2026.2 为参考，操作界面、信息密度、布局、图标和交互组织统一以 PyCharm 2026.2.1 New UI 为还原基线，但只实现本规格明确列出的能力。Augit 不捆绑 Git：优先使用用户在设置中指定的 `git.exe`，未指定时使用系统 `PATH` 中的 Git，Git for Windows 2.40 是全部 Git 能力的最低版本。Git 缺失或版本过低时保留文件浏览并禁用整个 Git 模块。所有命令都以当前工作区为执行目录，从而使用该仓库的 `.git`、仓库配置、hooks、凭据和 SSH 环境。Augit 不接管凭据。

本地只读 Git 查询最长执行 30 秒，超时后自动结束；网络操作和 Git 写操作不设置自动超时，只允许用户主动取消。取消后必须读取 Git 的实际状态，不把取消包装成成功。

### 5.1 改动与提交

- Changes 和 Unversioned Files 分组，每个文件只出现一次。
- diff 比较 HEAD 与磁盘最新内容，合并展示已经暂存和暂存后的后续变化。
- 只有新旧两侧内容都不超过 10 MB 且生成的 diff 不超过 20 MB 时才展示完整文本 diff；超过任一上限时停止生成正文，只显示文件状态和两侧大小，不生成可复制命令。
- 文件复选框决定提交哪些完整文件；文件被再次修改时不自动取消勾选。
- 提交不得意外带入未勾选但被外部工具暂存的文件。
- 支持 commit、amend 和 commit and push。
- 仓库实际生效的 hooks、`core.hooksPath` 或可识别的 commitlint 规则优先；没有可识别规则时，对用户在 Augit 中手工输入的 Commit 和 Amend 信息执行 Conventional Commits 1.0.0 兜底校验。
- 兜底校验只要求标题符合 `type(scope)!: description`、`type!: description` 或不带破坏性标记的对应形式，不限制 type 枚举和标题长度，正文与 footer 按规范处理；Git 自动生成的 merge、revert 和 rebase 信息不使用该兜底校验。
- 完整执行仓库 hooks 和签名配置，不提供跳过校验按钮。
- 支持单栏/双栏 diff、字词级变化、忽略空白差异、重命名识别、二进制摘要、文件历史、blame 和提交图。
- 不提供 Git Console 或 Git 操作历史；命令失败时只在当前操作界面临时显示脱敏输出，关闭后不保留。

### 5.2 仓库、远端与历史

- 支持 clone、init、fetch、pull、普通 push 和 remote 管理。
- 支持分支与标签的创建、切换、重命名、删除、推送和比较。
- 支持提交信息、哈希、作者、日期、分支和文件路径筛选历史。
- 认证由 Git Credential Manager、SSH agent 或终端处理，Augit 不保存凭据。
- 图形 Git 命令需要交互输入时停止执行并明确提示原因，不提供原命令复制或终端重试入口。
- 本机其他工具修改文件、索引、分支、提交或跟踪状态后，Augit 在 500 毫秒内刷新本地状态。
- 本机外部工具完成 push 后，只反映由此产生的本地 Git 状态变化。
- 远端被其他电脑修改时，Augit 不自动探测；只有用户主动 fetch 或 pull 后才更新远端状态。

### 5.3 工作区操作与冲突

- 支持 merge、rebase、cherry-pick、revert、stash、unstash 和 reset。
- 支持 Smart Checkout，必要时临时 stash 并在切换后恢复。
- 支持创建、打开和安全移除 worktree，每个 worktree 使用独立窗口。
- 三栏冲突解决器展示当前分支、最终结果和合入内容，并根据 IntelliJ IDEA 2026.2 New UI 及当前 Git 操作状态提供实际可用的 Continue、Skip 和 Abort 动作，不显示无效动作。
- 三栏冲突解决器只处理不超过 10 MB 的有效 UTF-8 文本；二进制、非法 UTF-8 和超限文件不进入三栏编辑，只提供 Accept Yours、Accept Theirs 和使用外部工具处理。
- 外部 AI、终端或其他工具解决冲突后自动同步最新本地状态。
- reset hard、rollback、删除分支或标签等会丢失数据的操作，必须先展示影响并明确确认。
- 未跟踪文件删除进入 Windows 回收站；worktree 只在干净且对应 Augit 窗口没有运行中的内置终端会话时允许安全移除，外部终端不在检测范围内。

### 5.4 明确排除的 Git 能力

- 不提供 Force Push。
- 不接入 GitHub、GitLab 等托管平台 API。
- 不在单窗口管理多个仓库。
- 不支持 Git 子模块，也不检测、不提示或提供任何子模块操作。
- 不提供多个 Changelist。

## 6. 终端

- 提供按需加载的内置终端，首版单会话，支持 PowerShell、CMD、Git Bash、WSL 和用户自定义启动命令。
- 内置终端默认在当前工作区根目录启动；文件树右键打开外部终端时，目录项使用该目录，文件项使用其所在目录。
- 首次默认使用 Windows PowerShell；只有用户主动选择后才使用 PowerShell 7、CMD、Git Bash、WSL 或自定义命令，已配置命令失效时明确报错，不静默回退。
- 终端最多保留最近 2000 行，超过上限时自动丢弃最旧内容，不提供无限滚动。
- 关闭内置终端时，空闲 shell 直接结束；存在运行中的前台命令时先明确提示，用户确认后结束该命令及其整个子进程树。终端会话不在启动时恢复。
- 同时提供在独立外部终端打开当前目录的入口。
- 未打开终端时不创建终端控件或 shell 进程。
- shell、WSL 等按需资源必须单独记录增量并通过资源回收验收。

## 6.1 内存指标口径

- 主界面由 WebView2 承载（见 UX 规格的主界面实现基线），WebView2 属**常驻**依赖，不再是按需资源，其进程树必须计入核心界面内存。
- WebView2 采用 Chromium 多进程架构（浏览器、渲染、GPU、网络等），其固有多进程开销使 100 MB Working Set 目标不可达。经用户确认，该数值目标已放开，改为「尽可能少」；当前实测约 540–560 MB（主进程约 60 MB + 6 个 WebView2 进程约 480–500 MB）。
- 后续内存测量必须按父进程关系把 WebView2 进程树归属到本实例。只统计主进程会低估真实占用，只统计同名进程会把其他应用的浏览器进程计入。

## 7. 外观、启动与本地数据

- 固定结构：左侧顶部切换项目、提交和搜索，左侧底部切换终端和 Git 历史；中间为只读文件标签；终端与 Git 历史在底部工具区按需展开且互斥显示，打开底部工具区时不隐藏项目树和文件内容。
- 项目或提交工具区与正文之间、正文与底部工具区之间的分隔位置可以拖动调整，并随本地设置恢复；图标按钮必须提供悬停说明。
- 布局、信息密度、面板结构、浅色/深色配色逻辑、交互节奏和已有功能图标以 PyCharm 2026.2.1 New UI 为最高还原目标；在 Augit 自身产品范围内尽可能 100% 复原其 UI 和使用体验。100% 是产品的理想目标，允许采用像素级复制，也允许采用其他能达到同等视觉与交互效果的实现方式，不要求所有平台渲染像素绝对相等；持续对照并记录尚存差异，不能将局部完成写成整体达成。
- 功能图标必须与 PyCharm 对应场景中的图标保持相同的轮廓、比例、线宽、填充、位置、颜色和状态，不能用语义相近但外形不同的图标替代；参考菜单没有图标的位置也保持空图标列。使用项目内自绘等效实现，不分发 JetBrains 官方资源文件、字体文件、商标或产品标志，不引入 Augit 产品规格之外的能力。Augit 自有品牌标记保留为唯一品牌例外。
- 列表拥有键盘焦点时，选中行使用参考蓝色；焦点移出列表（包括同一工具窗口的输入框或按钮）后保留选中项并切换为参考中性灰色。该状态变化不取消选择、不打开文件、不请求 Diff，也不改变 Git 文件勾选状态。
- 支持浅色、深色和跟随 Windows，默认跟随系统；主题覆盖包括 diff 在内的整体界面。
- 界面字体、界面字号、等宽字体和等宽字号分别设置，互不覆盖；默认界面正文为 13px，默认等宽正文为 13px，均指 96 DPI 逻辑像素。界面设置作用于文件树、标签、工具窗口、菜单、按钮和状态栏，等宽设置作用于只读正文、Diff、冲突三栏和终端；Markdown 预览正文跟随界面设置，代码块跟随等宽设置。设置立即生效并在重启后保留；不提供主题市场或自定义 CSS。
- 普通启动恢复上次目录；命令行和资源管理器右键可打开指定目录。
- 设置、最近目录、窗口、标签和文件树展开状态保存在 `%LOCALAPPDATA%\Augit`，不向仓库写工具配置。
- 启动时恢复标签顺序，但只读取并创建当前活动标签的文件视图；其他恢复标签在用户首次选择时按需读取，不得在启动阶段批量加载全部文件。
- 不做遥测、崩溃上报和自动更新检查，不启动常驻服务。
- 首版只提供简体中文界面，但界面文字集中管理。
- .NET 10 Runtime 和 WebView2 Runtime 是安装版的必备依赖。安装版使用小型联网安装程序，检测到缺失运行时后先明确告知用户，经确认后从微软官方下载并安装锁定的兼容版本，不提供包含完整运行时的离线安装包。
- 便携压缩包不自动安装运行时；缺少任一必备运行时时只说明缺失项并提供官方下载入口。

## 8. 明确不做

- AI 集成、代码生成和 AI 任务信息。
- 普通代码编辑、保存、语法高亮、代码补全、括号匹配、自动缩进和代码折叠。
- 调试器、构建系统和插件市场。
- Git 子模块、托管平台接口、Force Push 和单窗口多仓库。
- HTML、XML、YAML、CSV 等额外专用预览。
- 非 UTF-8 文本兼容、编码猜测和文件编码转换。
- 不提供 GIF、WebP 预览和 Markdown 原生 HTML 预览。

## 9. 交付阶段

实施按以下可运行阶段推进：

1. 轻量只读文件查看器。
2. IDEA 风格基础 Git 工作流。
3. Git 历史、分支与工作区管理。
4. 高级 Git 操作与三栏冲突解决。
