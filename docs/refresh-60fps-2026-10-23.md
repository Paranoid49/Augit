# 60fps 全窗刷新首内容测量（2026-10-23）

## 1. 目的

在正常入口、当前 HEAD `d26f226` 上，用 60fps 屏幕采集重新测一次“外部文件修改 → 编辑区出现新内容”的滞后，确认旧的全窗首内容 731.7/494.7/462.5/480.2ms 是否仍适用于当前构建。

## 2. 方法

- 正常入口：PID 30628，Light，DPI168，最大化，工作区为隔离临时仓库；README.md 在编辑器中打开，单标签。
- 采集：ffmpeg gdigrab，60fps，裁切 `x=760,y=200,w=800,h=500`（编辑正文左上区域），raw gray 输出。
- 计时：
  1. 启动 ffmpeg 后轮询 raw 文件长度，达到一帧（400,000 字节）时记为 `t0`；
  2. `t0 + 824ms` 时向 README.md 追加一行并记 `tWrite`；
  3. 采集结束，用基线帧逐像素统计变化，找连续 3 帧变化像素 >200 的第一帧为 `contentOnset`；
  4. 刷新滞后 = `contentOnset / 60 - (tWrite - t0)`。

这是一次对照测量，不是逐帧产品验收：`t0` 是 raw 首帧落盘时刻，不是合成器呈现时刻；结果为单次、单屏、裁剪区域。

## 3. 结果

- 采集 300 帧（5 秒）。
- 首个变化帧：**68**（1133.3ms after t0）。
- `tWrite - t0`：**824ms**。
- 编辑区首内容滞后：**309.3ms**。
- 首帧截图：`artifacts/refresh-60fps-2026-10-23/start.png`。
- 首内容帧：`artifacts/refresh-60fps-2026-10-23/onset.png`（可见新追加行）。

旧的全窗证据 731.7/494.7/462.5/480.2ms 采于 2026-10-17 的 GDI 录像；本结果不能直接说明当前所有刷新路径都低于 500ms，但至少说明当前构建的这条正常入口编辑区刷新在该样本中约 **309ms**，没有复现旧的 731.7ms。

## 4. 边界

- `t0` 轮询有最坏约一帧的延迟，且 raw 写入可能分块；309ms 应保留 ±16.7ms 采样与落盘误差，不能当成精确毫秒值。
- 只测编辑区裁切，不是全窗；不能证明标题栏、工具窗、状态栏无白帧。
- 只测 Light；未测深色、外部分支变化、冲突同步、透明帧/白帧。
- 只测一次；不替代 4 轮全窗视频。
- 临时 README 追加行已清除，临时 raw 已删除。

## 5. 全窗 4 轮 60fps

同一正常入口连续采集 4 轮全屏 H.264 60fps，同时用编辑区 raw gray 计时：

| 轮次 | 编辑区首内容 | 全屏帧数 | 全白帧 | 全黑帧 |
| --- | --- | --- | --- | --- |
| 1（前一轮） | **380.0ms** | 358 | 0 | 0 |
| 2 | **406.7ms** | 299 | 0 | 0 |
| 3 | **287.0ms** | 299 | 0 | 0 |
| 4 | **259.3ms** | 297 | 0 | 0 |

- 后 3 轮每轮开始前把 README 恢复到原状并等待 900ms，避免上一轮追加行尚未刷新造成假基线；4 轮的结果都低于 500ms。
- 全屏视频含任务栏，不是纯客户区；按 360×225 缩放后逐帧平均亮度 249，全白帧和全黑帧均为 0。
- 第 1 轮全屏首变化帧截图：`artifacts/refresh-fullwindow-2026-10-23/onset-full.png`；第 2–4 轮原始视频已删除，只保留结果。
- 第 1 轮与后 3 轮的进程启动间隔不完全相同，不能把全屏首变化帧与编辑区帧直接相减；表中的滞后都用各自的编辑区 raw 计时。

限制：这只是“外部文件修改 → 编辑区首内容”这一条路径；全屏录制含任务栏，`t0` 仍为 raw 首帧落盘，误差 ±16.7ms；未覆盖深色、外部分支变化、冲突同步、透明帧、光标和工具提示。

## 7. 结论

当前构建的“外部文件修改 → 编辑区首内容”路径：浅色全窗 4 轮 **380.0/406.7/287.0/259.3ms**，深色 2 轮 **360.3/320.3ms**，6 轮全屏均未出现全白/全黑帧。旧 731.7/494.7/462.5/480.2ms 不能再直接作为当前构建结论；但这仍不是全场景刷新验收，外部分支变化、冲突同步、透明帧和全窗像素仍未完成。
